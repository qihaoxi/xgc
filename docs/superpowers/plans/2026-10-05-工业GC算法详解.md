## Task 1: Serial / Parallel（分代与吞吐优先，系列地基）

**文件**：`docs/serial-parallel-算法详解/serial-parallel-算法详解.md` + `figures/sp-*.puml/png`

**必须讲清**：
- 弱分代假说；Eden/S0/S1/Old 布局；对象年龄与晋升阈值
- Minor GC 复制流程（含分配失败回退 Full GC）；TLAB 与 bump-pointer
- 卡表（512B/卡）、写屏障、记忆集：老年代→年轻代引用如何被当作根
- Full GC：标记-整理 LISP2 四阶段（标记 / 计算转发地址 / 更新引用 / 移动）
- Parallel Scavenge + Parallel Old；工作窃取并行复制；自适应调节（MaxGCPauseMillis / GCTimeRatio / 自适应 Eden）
- 停顿与存活对象量成正比；吞吐最优、延迟最差；适用场景

**图**：分代堆布局、复制收集、卡表+写屏障、晋升与 TLAB、LISP2 四阶段、并行工作窃取、回收状态机、时间线

## Task 2: CMS（首个主流并发收集器）

**文件**：`docs/cms-算法详解/cms-算法详解.md` + `figures/cms-*.puml/png`

**必须讲清**：
- ParNew(年轻代) + CMS(老年代) 组合；历史（JDK 5 引入 / 9 标记废弃 / 14 移除）
- 六阶段：initial mark(STW)、concurrent mark、concurrent preclean、remark(STW)、concurrent sweep、concurrent reset
- 增量更新（Dijkstra）写屏障 + 卡表 + mod-union table；preclean 如何缩短 remark
- 并发标记正确性论证（黑→白边出现时把白变灰）
- 空闲列表分配 → 碎片；promotion failure / concurrent mode failure → 回退 STW 全堆标记整理
- floating garbage（浮动垃圾）；参数：CMSInitiatingOccupancyFraction、CMSTriggerRatio、CMSScavengeBeforeRemark
- 为什么被 G1 取代：碎片、CMF、remark 长停顿、无压缩

**图**：分代堆+卡表、六阶段状态机、增量更新写屏障、卡表/mod-union、remark 重扫来源、并发清除+空闲列表、碎片与 CMF 回退、时间线

## Task 3: G1（JDK 9+ 默认）

**文件**：`docs/g1-算法详解/g1-算法详解.md` + `figures/g1-*.puml/png`

**必须讲清**：
- Region 化（1–32MB 2 的幂、~2048 个）、Humongous 对象（≥ region/2）、空闲列表
- 逻辑分代：Eden/Survivor/Old 是 region 集合；Young GC（STW 疏散）
- 并发标记周期：Initial Mark(STW, 搭车 Young GC) / Root Region Scanning / Concurrent Mark / Remark(STW) / Cleanup(STW+并发)
- TAMS（prev/next）与 SATB 快照；SATB pre-write barrier 记录被覆盖旧值
- 记忆集 + 卡表 + PRT + 并发 Refinement 线程；post-write barrier
- CSet 选取（Garbage First + 停顿预测模型：根扫描/RS 扫描/复制三部分成本）
- Mixed GC：年轻代 region + 高垃圾占比老年代 region；参数（G1HeapWastePercent、G1MixedGCLiveThresholdPercent、G1MixedGCCountTarget、InitiatingHeapOccupancyPercent=45、MaxGCPauseMillis=200）
- Evacuation 失败与 Full GC 回退（JDK10 起并行 Full GC）
- 转发指针在对象头 mark word；CAS 竞争与 self-forwarding

**图**：Region 堆布局、逻辑分代集合、RS/卡表/PRT、双写屏障、SATB 快照语义、TAMS 位图、标记周期状态机、Mixed CSet、停顿预测模型、时间线

## Task 4: Shenandoah（低延迟并发疏散）

**文件**：`docs/shenandoah-算法详解/shenandoah-算法详解.md` + `figures/sh-*.puml/png`

**必须讲清**：
- 定位：停顿与堆大小无关；JDK 12 实验 / 15 转正；与 G1 同 region 化但**并发疏散**
- Brooks 指针版：对象头额外 forwarding 字，访问先解引用；CAS 安装转发、自愈
- LRB 版（JDK 13+ 默认，Brooks 后续移除）：转发指针复用对象头、load reference barrier 在读取时自愈
- 并发标记（SATB）+ 并发疏散 + 并发更新引用（update refs）
- 阶段状态机：Init Mark(STW) / Concurrent Mark / Final Mark(STW) / Concurrent Cleanup / Concurrent Evacuation / Init+Concurrent+Final Update Refs / Final Cleanup
- CAS 转发竞争：GC 线程与 mutator 都可能搬对象，单赢家安装转发指针
- update refs 阶段如何保证"所有引用最终指向新副本"；load barrier 自愈的分摊
- Degenerated GC 与 Full GC 回退；heuristics（adaptive/static/compact/aggressive）与 pacing
- 与 G1/ZGC 三方对比表

**图**：Region+CSet、Brooks 指针、LRB 转发、SATB 标记、完整状态机、并发疏散+CAS、update refs、时间线

## Task 5: Go GC（非 Java 工业代表）

**文件**：`docs/go-gc-算法详解/go-gc-算法详解.md` + `figures/gogc-*.puml/png`

**必须讲清**：
- 非分代、非压缩、并发三色标记清除；GOGC 与 GOMEMLIMIT；两次极短 STW（mark setup / mark termination）
- 混合写屏障（Go 1.8+，Yuasa 删除屏障 + Dijkstra 插入屏障）为什么能消掉 mark termination 的栈重扫
- Mark assist：分配与标记赛跑时的债务/信用模型
- Pacer：目标堆大小、标记工作量、assist 比例反馈控制；触发时机
- 并发清除：span 的 allocBits/gcmarkBits 交换、lazy sweep、span 归还 mheap；finalizer 时序
- 运行时堆结构：mspan/size class/mcache/mcentral/mheap、tiny allocator、每 P 的 mcache
- 根：goroutine 栈（灰栈+异步抢占安全点）、全局、special/finalizer；栈写不设屏障的原因
- Green Tea（Go 1.25 实验）一句话即可，不得展开编造

**图**：运行时堆结构、非分代三色标记、混合写屏障、GC 周期（两次 STW）、Pacer 目标、mark assist、并发清除、时间线
