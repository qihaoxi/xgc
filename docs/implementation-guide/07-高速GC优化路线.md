# 07 — 高速 GC 优化路线

> 本文件描述 xgc 从"正确的 baseline"进化到"超高速 GC"的优化手段。每项优化标注**优先级**、**适用算法**、**实现复杂度**。

---

## 1. 优化原则

1. **先正确再快** — 优化不能破坏现有测试和 invariants
2. **先度量再改** — 每项优化前后必须有 benchmark 数据对比
3. **热路径优先** — 分配路径 > 写屏障路径 > 收集路径
4. **编译时零成本** — 未启用的优化路径不产生任何运行时开销

---

## 2. 分配路径优化

### 2.1 Bump-Pointer 分配（已实现于 gen-copy-ms）

```c
// 理想状态：分配只需 3 条机器指令
void* fast_alloc(gc_arena* arena, size_t size) {
    size_t aligned = (size + 7) & ~7;
    if (arena->used + aligned > arena->capacity) return NULL;  // slow path
    void* ptr = arena->base + arena->used;
    arena->used += aligned;
    return ptr;
}
```

**优先级**：P0（已实现 nursery bump-pointer）
**下一步**：把 `gc_alloc_typed` 中的 slow path（calloc fallback）改为 arena overflow → trigger minor GC → retry

### 2.2 Thread-Local Allocation Buffer (TLAB)

**目标**：多线程场景下消除分配路径上的原子操作。

```c
// 每个 thread_context 持有一块私有 buffer
struct gc_thread_context {
    ...
    uint8_t* tlab_base;
    size_t   tlab_used;
    size_t   tlab_capacity;  // 典型：32KB-128KB
};

// 分配时先尝试 TLAB（无锁）
void* gc_tlab_alloc(gc_thread_context* thread, size_t size) {
    size_t aligned = (size + 7) & ~7;
    if (thread->tlab_used + aligned > thread->tlab_capacity) {
        return NULL;  // TLAB 满 → 从全局 arena 重新申请一块
    }
    void* ptr = thread->tlab_base + thread->tlab_used;
    thread->tlab_used += aligned;
    return ptr;
}
```

**优先级**：P1（多线程模式的关键优化）
**适用**：所有算法
**复杂度**：中等（需要全局 arena 和 TLAB refill 逻辑）

### 2.3 Size-Class 分配器

**目标**：old gen 中非移动对象减少碎片。

```c
// 固定几个 size class：16, 32, 64, 128, 256, 512, 1024, 2048
// 每个 class 一个 freelist
typedef struct {
    gc_header* freelist;
    size_t     slot_size;
    size_t     allocated_count;
} gc_size_class;

typedef struct {
    gc_size_class classes[8];
    size_t        class_count;
} gc_size_class_allocator;
```

**优先级**：P2
**适用**：marksweep, gen-copy-ms 老年代
**复杂度**：中等

## 3. 写屏障优化

### 3.1 Conditional Barrier（已实现）

```c
// 当前：只在 old→young 时标脏
if (owner NOT in nursery AND new_value IN nursery):
    gc_barrier_mark_slot_dirty(rt, owner, slot)
```

这已经是正确的条件写屏障——大部分写入不触发 barrier 工作。

### 3.2 Card Table 查找优化

**当前问题**：`gc_card_table_find_entry` 是 O(n) 线性扫描。

**解法**：开放寻址哈希表，O(1) 查找。

```c
// hash(owner_base) → table->entries[hash & mask]
// 线性探测解决冲突
// 容量保持 2^n，load factor < 0.75 时 rehash
```

**优先级**：P0（已在路线图 Phase 1）
**复杂度**：低

### 3.3 Store Buffer（延迟写屏障）

**目标**：把 barrier 工作从 hot path 移到 GC 阶段。

```c
// 写屏障时只往 store buffer 追加一条记录
typedef struct {
    gc_header** slots;
    size_t      count;
    size_t      capacity;
} gc_store_buffer;

// write_barrier 变为：
store_buffer_push(thread->store_buffer, slot);

// GC 开始时 drain store buffer → 批量标脏 card table
```

**优先级**：P2（当 barrier 成为瓶颈时）
**适用**：分代 GC
**复杂度**：中等

## 4. 收集路径优化

### 4.1 Prefetch 优化

```c
// worklist drain 时，提前预取下一批对象
while (obj = gc_worklist_pop(&wl)):
    gc_header* next = wl.top > 0 ? wl.data[wl.top - 1] : NULL;
    if (next) __builtin_prefetch(next, 0, 1);
    obj->desc->trace_slots(obj, callback, ctx);
```

**优先级**：P2
**适用**：所有 tracing 算法
**复杂度**：低（一行 prefetch）

### 4.2 Parallel Marking

```c
// 多个 worker 线程并行 drain 同一个 work-stealing deque
// 每个 worker 有私有 local queue + 全局 shared queue
// 工作窃取：本地队列空时从其他 worker 偷

typedef struct {
    gc_header** buffer;
    _Atomic size_t top;
    _Atomic size_t bottom;
} gc_work_stealing_deque;
```

**优先级**：P3（需要多线程基础设施稳定后）
**适用**：marksweep, gen-copy 的 mark 阶段
**复杂度**：高

### 4.3 Lazy Sweep

```c
// 不在 GC 阶段一次性 sweep 全堆
// 而是在分配时按需 sweep：
void* lazy_sweep_alloc(state, size):
    while state->sweep_cursor:
        node = state->sweep_cursor
        state->sweep_cursor = node->next
        if !node->marked:
            // 回收这个 node，复用其内存
            gc_reclaim_object(rt, node->obj)
            free(node)
            // 从 freelist 分配
            return freelist_alloc(size)
    // sweep 完了还没找到 → 扩展堆
    return heap_expand_and_alloc(size)
```

**优先级**：P2
**适用**：marksweep
**复杂度**：中等

## 5. 原子操作 vs 无锁并发策略

### 5.1 哪些路径需要原子操作

| 路径 | 单线程 | 多线程 |
|------|--------|--------|
| `rc++` / `rc--` | 普通递增 | `atomic_fetch_add` / `atomic_fetch_sub` |
| `gc_state` 读写 | 普通赋值 | `atomic_load` / `atomic_store` |
| card table dirty bit | 普通位操作 | 可容忍非原子（worst case: 多标一次脏） |
| worklist push/pop | 普通栈操作 | 需要 work-stealing deque 或加锁 |
| purple buffer push | 普通数组操作 | 每线程独立 buffer（无竞争） |
| global object list | 普通链表操作 | CAS head-insert 或 TLAB 批量 flush |

### 5.2 减少原子操作的策略

| 策略 | 效果 | 适用 |
|------|------|------|
| **TLAB** | 分配路径零原子 | 分配 |
| **每线程独立 purple buffer** | push 无竞争 | RC cycle |
| **Epoch-based 延迟回收** | 减少 CAS 竞争 | 对象链表管理 |
| **Deferred RC** | 栈操作不增减 RC | RC 热路径 |
| **Biased locking** | 单线程拥有对象时不用原子 | RC |
| **Card table 非原子写** | 多线程同时标脏同一个 byte 无害 | 分代 GC 写屏障 |

### 5.3 无锁数据结构

**全局对象链表**：CAS head-insert
```c
void gc_global_list_insert(gc_runtime* rt, GcNode* node) {
    do {
        node->next = rt->global_head;
    } while (!CAS(&rt->global_head, &node->next, node));
}
```

**Work-stealing deque**（Parallel marking 用）：
```c
// Chase-Lev deque: owner push/pop 本端; thief steal 另一端
// push: buffer[bottom++] = obj  (本线程独占)
// pop:  obj = buffer[--bottom]  (本线程独占，底部为空时检查 top)
// steal: obj = buffer[top++]    (CAS 竞争)
```

### 5.4 避免 false sharing

```c
// 每个 thread_context 的热字段对齐到 cache line
struct gc_thread_context {
    gc_runtime* runtime;
    void*       vm_thread_ctx;
    void*       algo_state;
    // --- 以下是热路径字段，单独 cache line ---
    uint8_t     _pad[64 - 3 * sizeof(void*)];
    uint8_t*    tlab_base;
    size_t      tlab_used;
    size_t      tlab_capacity;
} __attribute__((aligned(64)));
```

## 6. 内存访问优化

### 6.1 对象布局优化

```
// 原始布局：gc_header + payload（可能有 padding）
// 优化布局：把 descriptor 指针替换为 index → 减少 header 到 8 字节
typedef struct gc_header_compact {
    uint16_t desc_index;    // descriptor 表中的索引
    uint16_t flags;
    uint32_t size;
} gc_header_compact;  // 仅 8 字节
```

**优先级**：P3（需要 descriptor 注册表）
**收益**：每对象省 8 字节，提高 cache 利用率

### 6.2 Nursery 局部性

Nursery bump-pointer 分配天然保证相邻分配的对象在内存中连续 → 极好的 cache 局部性。

**关键**：不要在 nursery 中做 free/reuse — 只在 GC 时整体 reset。

### 6.3 mark bitmap 与对象内存分离

```
// 不要在 gc_header 中放 mark bit
// 而是用 side-table bitmap：
//   mark_bits[object_index / 8] |= (1 << (object_index % 8))
// 好处：mark 阶段只写 bitmap 页，不污染对象 cache line
```

## 7. GC 触发策略优化

### 7.1 基于分配量的触发

```c
// 最简单：每分配 N 字节触发 minor GC
if (nursery_used >= nursery_capacity):
    collect_minor()
```

### 7.2 基于存活率的自适应触发

```c
// 跟踪上次 minor GC 的存活率
// 如果存活率高（大量对象晋升）→ 提前触发（减少一次 minor 的工作量）
// 如果存活率低（大量对象死亡）→ 延后触发（让更多短命对象死在 nursery 中）
size_t survival_rate = last_promoted_bytes / last_nursery_used;
if (survival_rate > 0.5):
    next_trigger_threshold = nursery_capacity / 2;
else:
    next_trigger_threshold = nursery_capacity;
```

### 7.3 GC Pacing（参考 Go GC）

```c
// 目标：GC 完成时堆增长不超过 GOGC% 
// 通过动态调整 GC 触发阈值 + worker assist 实现
// 核心公式：
//   trigger = live_after_last_gc * (1 + GOGC/100)
//   如果分配速率 > GC 处理速率 → mutator 被迫"纳税"帮助标记
```

**优先级**：P3
**适用**：并发 GC

## 8. 优化路线图总结

| 优先级 | 优化项 | 预期收益 | 依赖 |
|--------|--------|---------|------|
| P0 | card_table 哈希查找 | barrier 路径 10x | 无 |
| P0 | arena 分配器替代 calloc | alloc 路径 5-10x | Phase 3 |
| P1 | TLAB | 多线程分配零原子 | GC_MULTITHREAD |
| P1 | 每线程独立 purple buffer | RC push 零竞争 | bacon-rajan |
| P2 | store buffer | 写屏障延迟批处理 | 分代 GC |
| P2 | lazy sweep | 减少 STW 暂停 | marksweep |
| P2 | prefetch | 标记吞吐 ~20% | tracing |
| P2 | size-class allocator | old gen 减少碎片 | non-moving 算法 |
| P3 | parallel marking | 多核利用 | 并发基础设施 |
| P3 | work-stealing deque | 并行标记负载均衡 | 同上 |
| P3 | compact header (8B) | 每对象省 8B | descriptor 注册表 |
| P3 | GC pacing | 并发 GC 调度 | 并发 collector |

## 9. 性能度量标准

每项优化都需要用 benchmark 验证。关键指标：

| 指标 | 测量方法 | 目标 |
|------|---------|------|
| alloc throughput | `bench/alloc_small.c` — ops/sec | >100M obj/sec (bump-pointer) |
| store_ref latency | `bench/old_to_young_writes.c` — ns/store | <50ns (含 barrier) |
| minor GC pause | 时间戳 before/after collect_minor | <1ms (4MB nursery) |
| full GC pause | 时间戳 before/after collect_full | <10ms (64MB 堆) |
| peak RSS | `/proc/self/status` VmRSS | <2x live data |
| fragmentation | allocated_bytes / actual_heap_bytes | >0.8 |
