## 3. 每个 Step 的标准工作流

```
对每个 Step:
  1. 读对应详细文档章节
  2. 读文档 03（编码约束）确认不违反禁止行为
  3. 实现代码（参考文档 13 的可编译 C 模板）
  4. 写单元测试（参考文档 04 的模板）
  5. 在 cmake/tests.cmake 注册测试
  6. 运行验收命令
  7. 运行 ASan 验收
  8. git commit
  9. 才能进入下一个 Step

额外要求（算法类 Step G/I/J）：
  - 必须额外通过文档 19 的差分测试（影子预言机对比）+ 压力测试
  - 多线程相关 Step H：必须额外通过 TSan（文档 18 §8）
  - 完成后对照文档 15 §6 的「完成度自检清单」逐项确认
```

### 标准验收命令（每个 Step 都跑）

```bash
# 1. 默认算法构建 + 测试
cmake -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build 2>&1 | tee build.log
ctest --test-dir build --output-on-failure

# 2. ASan 验收（零报错才算通过）
cmake -B build-asan -DCMAKE_BUILD_TYPE=Debug -DSAN_ADDRESS=ON
cmake --build build-asan
ctest --test-dir build-asan --output-on-failure

# 3. 全算法回归（涉及算法切换的 Step 必须跑）
for algo in marksweep gen_copy_ms bacon-rajan; do
    cmake -B build-$algo -DGC_ALGORITHM=$algo -DCMAKE_BUILD_TYPE=Debug
    cmake --build build-$algo && ctest --test-dir build-$algo --output-on-failure
done
```

**判定标准**：
- 构建 0 警告（`-Werror` 保证）
- 所有测试 `Passed`
- ASan 0 报错（no leaks, no heap-buffer-overflow, no use-after-free）

## 4. 失败时的处理协议

```
如果验收命令失败：
  1. 不要继续下一个 Step
  2. 不要删除测试来"通过"
  3. 不要注释掉断言
  4. 读 build.log / ctest 输出，定位失败的文件:行号
  5. 如果是编译错误：检查是否引用了未定义的类型/函数 → 去文档 01/13 查
  6. 如果是断言失败：用 -DGC_DEBUG=ON 重新构建，看事件日志
  7. 如果是 ASan 报错：按报错的栈回溯定位 use-after-free / leak
  8. 修复后重新跑完整验收
```
