# 17 — 正确性验证、压力测试与模糊测试

> 单元测试只能覆盖已知场景。工业级 GC 的正确性靠**随机化压力测试 + 差分验证**保证 —— 用随机对象图 + 独立的"影子可达性预言机"对比 GC 的实际回收结果。

---

## 1. 三层验证体系

| 层 | 手段 | 覆盖 |
|----|------|------|
| L1 单元测试 | substrate test + smoke test | 已知场景、边界条件 |
| L2 差分测试 | 随机对象图 + 影子标记对比 | GC 决策的正确性 |
| L3 模糊/压力测试 | 长时间随机操作序列 | 罕见的并发/状态组合 bug |

---

## 2. 差分测试(Differential Testing)

### 2.1 核心思想

GC 的唯一正确性标准是:**回收且仅回收不可达对象**。我们用一个独立实现的"影子可达性计算"作为预言机(oracle),与 GC 的实际行为对比。

```
1. 构造随机对象图 G
2. 设置随机根集 R
3. 影子预言机:从 R 做 BFS,计算可达集 Reachable(G, R)
4. 触发 GC
5. 验证:
   - 所有 Reachable 对象仍存活（未被 finalize）
   - 所有 不可达 对象被回收（已 finalize，且数量正确）
```

### 2.2 影子预言机实现

```c
/* tests/oracle.h — 独立于 GC 的可达性计算 */

typedef struct {
    gc_header** all_objects;     /* 测试创建的所有对象 */
    size_t      object_count;
    gc_header** roots;           /* 当前根集 */
    size_t      root_count;
} oracle_graph;

/* 用一个独立的 visited 集合（不复用 GC 的标记位）计算可达性 */
static void oracle_mark_reachable(oracle_graph* g, uint8_t* reachable /* bitmap */) {
    /* 用独立 worklist,从 roots 做 BFS */
    gc_header** stack = malloc(g->object_count * sizeof(gc_header*));
    size_t top = 0;
    for (size_t i = 0; i < g->root_count; i++) {
        int idx = oracle_index_of(g, g->roots[i]);
        if (idx >= 0 && !reachable[idx]) {
            reachable[idx] = 1;
            stack[top++] = g->roots[i];
        }
    }
    while (top > 0) {
        gc_header* obj = stack[--top];
        /* 用测试已知的对象布局枚举子引用（不调用 GC 的 trace_slots,独立实现）*/
        oracle_for_each_child(obj, /* callback */ {
            int idx = oracle_index_of(g, child);
            if (idx >= 0 && !reachable[idx]) {
                reachable[idx] = 1;
                stack[top++] = child;
            }
        });
    }
    free(stack);
}
```

> **关键**:预言机**不能**复用 GC 的 `trace_slots` 或标记位 —— 否则 GC 和预言机有同样的 bug 就检测不出来。预言机用测试自己的对象布局知识独立计算。

### 2.3 差分测试主循环

```c
/* tests/test_differential.c */
int main(void) {
    unsigned seed = 12345;  /* 固定种子可复现;或用时间随机 */
    for (int round = 0; round < 1000; round++) {
        /* 1. 随机构造对象图 */
        oracle_graph g;
        build_random_graph(&g, &seed, /* node_count */ 50 + rand_r(&seed) % 200);

        /* 2. 随机选根 */
        pick_random_roots(&g, &seed);

        /* 3. 影子计算可达性 */
        uint8_t* reachable = calloc(g.object_count, 1);
        oracle_mark_reachable(&g, reachable);

        /* 4. 触发 GC */
        size_t finalized_before = vm.finalized_count;
        gc_collect_full(rt);

        /* 5. 验证可达对象仍存活 */
        for (size_t i = 0; i < g.object_count; i++) {
            if (reachable[i]) {
                assert(!was_finalized(g.all_objects[i]));  /* 活对象不该被回收 */
            }
        }

        /* 6. 验证回收数量 */
        size_t expected_dead = count_unreachable(&g, reachable);
        size_t actual_finalized = vm.finalized_count - finalized_before;
        assert(actual_finalized == expected_dead);

        /* 7. invariant */
        assert(gc_runtime_check_invariants(rt) == 1);

        free(reachable);
    }
    return EXIT_SUCCESS;
}
```

> **`was_finalized` 怎么实现**：上面用了 `was_finalized(obj)` 做逐对象判定，但 §2.2 只维护了全局 `vm.finalized_count`。补一个逐对象位图：在 `oracle_graph` 里加 `uint8_t* finalized`（与 `all_objects` 同长），finalize 回调里 `g->finalized[oracle_index_of(g, obj)] = 1`，`was_finalized(obj)` 就是查这个位图。**moving GC 注意**：finalize 回调收到的 `obj` 地址可能已被移动，回调里要用 handle 或在移动前记录的 index 定位--最稳是 finalize 回调通过 `obj->desc` 的某个 id 字段反查 index，或测试用 non-moving 算法先验差分逻辑。`oracle_index_of`/`oracle_for_each_child` 同理是测试侧辅助，按本节 §2.2 的 `oracle_graph` 结构实现（地址->index 用哈希或线性查 `all_objects`）。

### 3.2 必须覆盖的图形态

| 形态 | 生成参数 | 检验什么 |
|------|---------|---------|
| 线性链 | max_children=1, cycle=0 | 深度遍历不溢出 |
| 宽扇出 | max_children=100 | worklist 扩容 |
| 深树 | max_children=2, node=10000 | 深递归 |
| 密集环 | cycle_probability=80 | 环回收(RC 重灾区) |
| 自环 | 对象指向自己 | 边界 |
| 全可达 | root_ratio=100 | sweep 不误删 |
| 全垃圾 | root_ratio=0 | 全部回收 |
| 孤岛环 | 环但无根可达 | RC 必须靠 cycle collector |

## 4. 压力测试

### 4.1 长时间随机操作

```c
/* tests/test_stress.c */
int main(void) {
    double deadline = now_ms() + 10000;  /* 跑 10 秒 */
    while (now_ms() < deadline) {
        int op = rand() % 100;
        if (op < 50)       random_alloc();        /* 50% 分配 */
        else if (op < 75)  random_store_ref();     /* 25% 改引用 */
        else if (op < 85)  random_drop_root();     /* 10% 丢根 */
        else if (op < 95)  random_add_root();      /* 10% 加根 */
        else               gc_collect_full(rt);    /* 5% 主动 GC */

        /* 周期性检查 invariant + canary 对象未损坏 */
        if (op == 0) {
            assert(gc_runtime_check_invariants(rt) == 1);
            verify_canaries();
        }
    }
    return EXIT_SUCCESS;
}
```

### 4.2 Canary(金丝雀)对象

```c
/* 已知应当存活的对象,字段填充已知 magic 值 */
typedef struct {
    gc_header gc;
    uint64_t  magic;       /* 固定 0xCAFEBABE... */
    void*     child;
} CanaryObj;

void verify_canaries(void) {
    for (each canary held by root) {
        assert(canary->magic == 0xCAFEBABEDEADBEEF);  /* 未被破坏 */
        /* 如果是 moving GC,canary 地址可能变,通过 handle 取最新地址 */
    }
}
```

## 5. 模糊测试(Fuzzing)

### 5.1 操作序列模糊

把"GC 操作序列"编码为字节流,用 libFuzzer/AFL 喂随机字节,解码为操作:

```c
/* tests/fuzz_gc.c — libFuzzer 入口 */
int LLVMFuzzerTestOneInput(const uint8_t* data, size_t size) {
    gc_runtime* rt = setup_runtime();
    size_t pos = 0;
    while (pos < size) {
        uint8_t op = data[pos++];
        switch (op % 6) {
            case 0: fuzz_alloc(data, &pos, size); break;
            case 1: fuzz_store_ref(data, &pos, size); break;
            case 2: fuzz_collect_minor(rt); break;
            case 3: fuzz_collect_full(rt); break;
            case 4: fuzz_add_handle(data, &pos, size); break;
            case 5: fuzz_release_handle(data, &pos, size); break;
        }
        /* 每步后检查 invariant — 模糊测试的价值在于触发罕见状态 */
        assert(gc_runtime_check_invariants(rt) == 1);
    }
    teardown_runtime(rt);
    return 0;
}
```

### 5.2 模糊测试构建

```bash
clang -fsanitize=fuzzer,address -DGC_DEBUG=ON \
    tests/fuzz_gc.c -lxgc -o fuzz_gc
./fuzz_gc -max_total_time=300   # 跑 5 分钟
```

## 8. 实现顺序

```
1. 先写 oracle.h（影子可达性,独立实现）
2. 写 build_random_graph（随机图生成器）
3. 写 test_differential.c（固定种子,先跑 100 轮）
4. 对每个算法跑差分测试,修所有 mismatch
5. 加 test_stress.c（canary 验证）
6. 最后加模糊测试（可选,需要 libFuzzer）
7. 建立 tests/regression/ 语料库,持续积累
```
