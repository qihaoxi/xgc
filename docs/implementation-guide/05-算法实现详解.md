## A. Mark-Sweep STW

### A.1 核心思想

从 roots 出发追踪所有可达对象（mark），遍历全堆释放不可达对象（sweep）。STW = mutator 完全暂停。

### A.2 数据结构

```c
typedef struct GcMsNode {
    gc_header*        obj;
    uint8_t           marked;    // 或用 gc_bitmap 替代
    struct GcMsNode*  next;
} GcMsNode;

typedef struct {
    GcMsNode*   objects;         // 全对象链表
    gc_bitmap   mark_bits;       // side-metadata 替代（Phase 2 后）
    size_t      object_count;
} GcMarksweepState;
```

### A.3 详细算法步骤

```
collect_full(rt):
    state = rt->algo_state

    // ═══ Phase 1: Mark ═══
    wl = {rt->worklist_data, 0, rt->worklist_capacity}

    // 1a. 标记 handle roots
    for handle in rt->handles:
        node = find_node(state, handle->target)
        if node && !node->marked:
            node->marked = 1
            gc_worklist_push(&wl, node->obj)

    // 1b. 标记 VM roots
    rt->hooks.scan_roots(rt->hooks.vm_ctx, mark_root_slot_callback, &ctx)
    // callback 内部: find_node → marked=1 → push

    // 1c. drain worklist（追踪子引用）
    while (obj = gc_worklist_pop(&wl)) != NULL:
        obj->desc->trace_slots(obj, mark_child_callback, &ctx)
        // callback 内部: find_node(child) → if !marked → mark → push

    // ═══ Phase 2: Sweep ═══
    link = &state->objects
    while *link != NULL:
        node = *link
        if node->marked:
            node->marked = 0      // 重置为下轮准备
            link = &node->next
        else:
            *link = node->next
            gc_reclaim_object(rt, node->obj)
            free(node)
```

### A.4 关键实现陷阱

| 陷阱 | 说明 | 解法 |
|------|------|------|
| worklist 溢出 | 深对象图（>10000 层） | `gc_worklist_push` 内部 realloc 2x |
| sweep 时修改链表 | 删除当前节点后 link 断裂 | 用 `link = &(*link)->next` 指针间接法 |
| 环引用 | mark 天然处理 — 已 marked 的对象不重复入栈 | 无需额外处理 |
| handle 释放顺序 | handle 指向的对象在 sweep 期间不能被回收 | mark 阶段先标记所有 handle targets |

### A.5 性能特征

- 分配：O(1)（malloc + 链表头插）
- 回收：O(live + dead)（mark 遍历存活，sweep 遍历全堆）
- 暂停：与堆大小正相关
- 碎片：不移动对象，长期运行碎片化

## B. Generational Copying + Mark-Sweep

### B.1 核心思想

年轻代使用 bump-pointer 分配 + copying evacuation。老年代使用 mark-sweep。分代假设：大部分对象短命。

### B.2 数据结构

```c
typedef struct GcGenOldNode {
    gc_header*            obj;
    uint8_t               marked;
    struct GcGenOldNode*  next;
} GcGenOldNode;

typedef struct GcGenForward {
    gc_header*            from;     // nursery 中的旧地址
    gc_header*            to;       // old gen 中的新地址
    struct GcGenForward*  next;
} GcGenForward;

typedef struct {
    uint8_t*        nursery_space;      // bump-pointer 连续区域
    size_t          nursery_capacity;
    size_t          nursery_used;
    GcGenOldNode*   old_objects;         // 老年代链表
    GcGenForward*   forwarded;           // 本轮转发表
} GcGenCopyMsState;
```

### B.3 Minor GC 详细步骤

```
collect_minor(rt):
    state = rt->algo_state
    if state->nursery_used == 0: return

    used_before = state->nursery_used
    gc_gen_clear_forwarding(state)

    wl = {rt->worklist_data, 0, rt->worklist_capacity}
    ctx = {rt, state, &wl}

    // ═══ Step 1: Evacuate handle roots ═══
    for handle in rt->handles:
        handle->target = promote(ctx, handle->target)

    // ═══ Step 2: Evacuate VM roots ═══
    rt->hooks.scan_roots(vm_ctx, evacuate_slot_callback, &ctx)
    // callback: if *slot in nursery → *slot = promote(ctx, *slot)

    // ═══ Step 3: Scan dirty cards (old→young remembered set) ═══
    gc_barrier_visit_dirty_cards(rt, dirty_card_callback, &ctx)
    // callback(owner, card_index):
    //   byte_begin = card_index * card_granularity
    //   byte_end = byte_begin + card_granularity
    //   gc_trace_object_slots_in_range(owner, byte_begin, byte_end, evacuate_slot, ctx)

    // ═══ Step 4: Drain worklist ═══
    while (obj = gc_worklist_pop(&wl)):
        obj->desc->trace_slots(obj, evacuate_slot_callback, &ctx)

    // ═══ Step 5: Finalize dead nursery objects ═══
    cursor = nursery_space
    while cursor < nursery_space + used_before:
        obj = (gc_header*)cursor
        if not forwarded(obj) && obj->desc->finalize:
            obj->desc->finalize(obj)
        cursor += obj->size
    stats.total_allocated -= used_before

    // ═══ Step 6: Reset ═══
    state->nursery_used = 0
    gc_heap_reset_young(rt)
    gc_gen_clear_forwarding(state)
    // 清除所有 dirty cards（已在 Step 3 callback 中逐 owner 清除）
```

### B.4 promote() 详细逻辑

```c
gc_header* promote(ctx, obj):
    if obj not in nursery: return obj       // 已经是 old gen
    if forwarded(obj): return forward[obj]  // 已复制

    // 复制到老年代
    copy = malloc(obj->size)
    memcpy(copy, obj, obj->size)

    // 注册到老年代管理结构
    gc_gen_add_old_node(rt, state, copy)    // 含 gc_barrier_register_owner

    // 建立转发映射
    forward_table_insert(state, obj → copy)

    // 更新统计
    stats.total_allocated += copy->size

    // 推入 worklist（新复制的对象的子引用还需要更新）
    gc_worklist_push(wl, copy)

    return copy
```

### B.5 写屏障逻辑

```c
write_barrier(rt, thread, owner, slot, old_value, new_value):
    if owner NOT in nursery AND new_value IN nursery:
        gc_barrier_mark_slot_dirty(rt, owner, slot)
```

### B.6 关键陷阱

| 陷阱 | 说明 | 解法 |
|------|------|------|
| 重复 promote | 同一对象被多条引用指向 | forwarding table 去重 |
| dirty card 遍历时 owner 被修改 | 应在遍历后统一清除 | 先记录待清除 owner 列表，遍历完再批量清 |
| pinned 对象不能移动 | nursery 中 pinned 对象 | 分配时直接进 old gen |
| large object 不走 nursery | 大对象在 nursery 中浪费空间 | 超过阈值直接 calloc 进 old |
| 对象 size 对齐 | bump-pointer 需要对齐 | `aligned_size = (size + 7) & ~7` |

### B.7 Full GC 流程

```
collect_full(rt):
    collect_minor(rt)    // 先处理年轻代
    // 然后对 old gen 做 mark-sweep（同 Algorithm A，但只对 old_objects 链表）
```

## C. Generational Copying + Mark-Compact

### C.1 相对 B 的变化

年轻代不变（copying）。老年代从 mark-sweep 升级为 mark-compact（LISP2 算法）。

### C.2 LISP2 Compaction 四阶段

```
compact_old(rt, state):

    // ═══ Phase 1: Mark ═══
    // 同 mark-sweep 的 mark 阶段（worklist + trace_slots）

    // ═══ Phase 2: Compute Forwarding ═══
    free_ptr = old_space_start
    for node in old_objects (按地址顺序):
        if node->marked:
            forwarding[node->obj] = free_ptr
            free_ptr += node->obj->size
        // else: dead, skip

    // ═══ Phase 3: Update References ═══
    // 更新所有 root slots
    rt->hooks.scan_roots(vm_ctx, update_ref_callback, forwarding)
    // callback: if *slot in forwarding → *slot = forwarding[*slot]

    // 更新所有存活对象的内部引用
    for node in old_objects:
        if node->marked:
            node->obj->desc->trace_slots(node->obj, update_ref_callback, forwarding)

    // 更新 handle targets
    for handle in rt->handles:
        if handle->target in forwarding:
            handle->target = forwarding[handle->target]

    // ═══ Phase 4: Move Objects ═══
    for node in old_objects:
        if node->marked:
            dest = forwarding[node->obj]
            if dest != node->obj:
                memmove(dest, node->obj, node->obj->size)
            node->obj = dest
            node->marked = 0
```

### C.3 Pinned 对象处理

Pinned 对象不移动。Phase 2 计算 forwarding 时跳过 pinned 对象（在原地保留）：

```
// Phase 2 修正：
free_ptr = old_space_start
for node in old_objects (地址顺序):
    if !node->marked: continue
    if node->obj->flags & GC_OBJECT_FLAG_PINNED:
        forwarding[node->obj] = node->obj    // 不移动
        free_ptr = max(free_ptr, node->obj + node->obj->size)
    else:
        forwarding[node->obj] = free_ptr
        free_ptr += node->obj->size
```

### C.4 关键陷阱

| 陷阱 | 说明 | 解法 |
|------|------|------|
| memmove 重叠 | 压缩方向与对象排列方向一致时可能重叠 | 用 `memmove` 而非 `memcpy` |
| descriptor 指针 | 移动后 `obj->desc` 仍指向原来的静态 descriptor — 不变 | 无需处理（desc 是静态的） |
| forwarding table 内存 | 对象多时 table 大 | 用 side-metadata bitmap 或哈希 |
| Phase 3/4 顺序 | 必须先 update 再 move，否则旧地址的 trace_slots 会读到脏数据 | 严格顺序 |

## D. RC + Bacon-Rajan Cycle Collector

### D.1 核心思想

- 写屏障中做 retain/release — 无环对象归零时立即释放
- 环通过 Bacon-Rajan Trial Deletion 检测

### D.2 数据结构

```c
typedef enum {
    RC_COLOR_BLACK  = 0,    // 正常存活
    RC_COLOR_GRAY   = 1,    // 正在 trial deletion
    RC_COLOR_WHITE  = 2,    // 确认垃圾
    RC_COLOR_PURPLE = 3,    // 嫌疑
} RcColor;

typedef struct GcRcNode {
    gc_header*        obj;
    uint32_t          rc;           // 堆引用计数（栈不计数 — deferred RC）
    uint32_t          gc_ref;       // trial deletion 工作计数
    uint8_t           color;
    uint8_t           in_purple;
    struct GcRcNode*  next;         // 全对象链表
} GcRcNode;

typedef struct {
    GcRcNode*    objects;            // 全对象链表
    GcRcNode**   purple_buffer;      // 嫌疑人数组
    int          purple_count;
    int          purple_capacity;    // 自适应范围 [64, 4096]
    gc_worklist  wl;                 // 共享工作栈
} GcBaconRajanState;
```

### D.3 写屏障（堆引用赋值时触发）

```c
write_barrier(rt, thread, owner, slot, old_value, new_value):
    // retain new
    if new_value:
        rc_node(new_value)->rc++
        if rc_node(new_value)->color == WHITE:
            rc_node(new_value)->color = BLACK

    // release old
    if old_value:
        node = rc_node(old_value)
        node->rc--
        if node->rc == 0:
            // 立即释放（递归 release 子引用）
            release_recursive(rt, node)
        else:
            // RC 减少但未归零 → 可能是环的一部分
            if node->color != PURPLE && !node->in_purple:
                node->color = PURPLE
                node->in_purple = 1
                purple_buffer_push(state, node)
```

### D.4 release_recursive

```c
release_recursive(rt, node):
    node->color = BLACK
    node->obj->desc->trace_slots(node->obj, release_child_callback, ctx)
    // callback: child_node->rc--; if rc==0 → release_recursive
    gc_reclaim_object(rt, node->obj)
    // 从全对象链表移除 node
```

**关键**：递归可能很深 → 改用显式 worklist 迭代。

### D.5 Trial Deletion（collect_full）

```c
collect_full(rt):
    state = rt->algo_state
    n = state->purple_count
    buf = state->purple_buffer

    // ═══ Phase 1: 复制 RC → gc_ref，染灰 ═══
    for i in 0..n:
        node = buf[i]
        node->gc_ref = node->rc
        node->color = GRAY
        node->in_purple = 0

    // ═══ Phase 2: 减去内部引用 ═══
    // 将所有嫌疑人压入工作栈
    for i in 0..n:
        gc_worklist_push(&wl, buf[i]->obj)

    while (obj = gc_worklist_pop(&wl)):
        obj->desc->trace_slots(obj, subtract_callback, ctx)
        // callback(child_slot):
        //   child = *child_slot
        //   child_node = rc_node(child)
        //   if child_node->color == GRAY:
        //       child_node->gc_ref--
        //       gc_worklist_push(&wl, child)

    // ═══ Phase 2.5: 栈根保护 ═══
    // 扫描 roots → 如果 root 指向 GRAY 对象 → 递归回滚为 BLACK + gc_ref++
    rt->hooks.scan_roots(vm_ctx, protect_root_callback, ctx)
    // callback: if root_node->color == GRAY:
    //   root_node->gc_ref++
    //   root_node->color = BLACK
    //   递归保护子引用（trace_slots → 如果 child 是 GRAY → gc_ref++ → BLACK → push）

    // ═══ Phase 3: 分离存活与垃圾 ═══
    alive_count = 0
    for i in 0..n:
        node = buf[i]
        if node->gc_ref > 0 || node->color == BLACK:
            node->color = BLACK
            buf[alive_count++] = node
        else:
            node->color = WHITE

    // ═══ Phase 4: 释放垃圾 ═══
    for i in 0..n:
        node = buf[i]
        if node->color == WHITE:
            gc_reclaim_object(rt, node->obj)
            remove_from_object_list(state, node)

    state->purple_count = alive_count

    // ═══ 自适应调整 ═══
    freed = n - alive_count
    if freed > n/2: capacity /= 2
    else: capacity *= 2
    clamp(capacity, GC_PURPLE_CAPACITY_MIN, GC_PURPLE_CAPACITY_MAX)
```

### D.6 为什么需要 Phase 2.5（栈根保护）

延迟 RC 下栈引用不增减 RC。如果栈持有对象 A，但 A 的 `rc==0`（仅栈引用），Trial Deletion 的 Phase 2 会把 A 的子孙也减光。Phase 3 中 A 的 gc_ref 可能为 0 → 被误判为垃圾。

**解法**：Phase 2 之后、Phase 3 之前，扫描栈。如果栈引用了 GRAY 对象 → 递归回滚整个子图。

### D.7 关键陷阱

| 陷阱 | 说明 | 解法 |
|------|------|------|
| gc_ref 可能为负 | 同一对象被重复引用 → subtract 多次 | 负值也判为垃圾（同 CPython） |
| Phase 2 未遍历完整子图 | 只遍历 buf 中对象的直接子节点不够 | 必须用 worklist 深度优先遍历整张 GRAY 子图 |
| 并发写屏障干扰 | Trial Deletion 期间 mutator 写屏障修改颜色 | 多线程时需 Epoch 机制（见 §E） |
| release_recursive 栈溢出 | 长链对象逐个释放 | 用 worklist 迭代代替递归 |
| 紫色缓冲区满 | 满时触发 collect_full | on_purple_buffer_full 回调 |

## E. Incremental Tri-Color Mark-Sweep

### E.1 核心思想

把 mark 阶段拆成多个小步骤（increments），每步后允许 mutator 运行。使用**写屏障**维护三色不变式。

### E.2 增量标记的步进模型

```c
typedef struct {
    gc_worklist gray_set;       // 灰色对象集合
    int         marking_active; // 是否正在增量标记
    size_t      mark_step_budget; // 每步处理多少对象
} GcIncrementalState;
```

### E.3 mark_step

```c
void mark_step(rt, budget):
    state = rt->algo_state
    processed = 0
    while processed < budget && (obj = gc_worklist_pop(&state->gray_set)):
        obj->desc->trace_slots(obj, mark_child_callback, ctx)
        // callback: if child 是白色 → 染灰 → push
        set_black(obj)
        processed++

    if state->gray_set is empty:
        // 标记完成 → sweep
        sweep(rt)
        state->marking_active = 0
```

### E.4 写屏障（Incremental Update 风格）

```c
write_barrier(rt, thread, owner, slot, old_value, new_value):
    if !state->marking_active: return
    // 如果黑色对象指向了白色对象 → 重新染灰
    if is_black(owner) && is_white(new_value):
        set_gray(owner)
        gc_worklist_push(&state->gray_set, owner)
```

### E.5 SATB 替代方案

```c
write_barrier_satb(rt, thread, owner, slot, old_value, new_value):
    if !state->marking_active: return
    // 保存旧值 — 快照时刻存在的对象都算活的
    if is_white(old_value):
        set_gray(old_value)
        gc_worklist_push(&state->gray_set, old_value)
```

### E.6 触发时机

- 分配 N 字节后自动触发 `mark_step(budget=100)`
- 或在 `gc_alloc_typed` 中嵌入小步骤

## F. Regional Concurrent Collector

### F.1 核心思想

堆被分成固定大小的 region。并发标记线程与 mutator 同时运行。疏散（evacuation）时选择存活率最低的 region 复制到新 region。

### F.2 数据结构

```c
typedef struct GcRegion {
    uint8_t*    base;
    size_t      capacity;
    size_t      used;
    size_t      live_bytes;    // 标记后计算
    uint8_t     generation;    // 0=young, 1=old
    gc_bitmap   mark_bits;
} GcRegion;

typedef struct {
    GcRegion*   regions;
    size_t      region_count;
    size_t      region_capacity;
    size_t      region_size;        // 固定大小（如 256KB）
    gc_worklist mark_worklist;      // 并发标记 worklist
    int         concurrent_marking; // 标记线程是否活跃
} GcRegionalState;
```

### F.3 并发标记阶段

```
concurrent_mark(rt):
    // 1. 初始标记（STW，很短）
    pause_mutators()
    scan_roots → 入 mark_worklist
    resume_mutators()

    // 2. 并发标记（mutator 同时运行）
    while (obj = gc_worklist_pop(&mark_worklist)):
        for each child_slot in obj:
            child = *child_slot
            if !marked(child):
                mark(child)
                gc_worklist_push(&mark_worklist, child)
    // 写屏障（SATB）在此期间把被覆盖的旧值压入 mark_worklist

    // 3. 最终标记（STW，处理残余灰色）
    pause_mutators()
    drain_remaining_gray()
    resume_mutators()
```

### F.4 疏散（Evacuation）

> **两个层次**：下面是 **STW 疏散**（停顿与存活集成正比，先实现这个作为正确性基线）。要做到**与堆解耦的亚毫秒停顿**（ZGC/Shenandoah 级），把这里的 STW evacuate 替换为**并发重定位**（读屏障 + 染色指针 + lazy remap），完整机制见 **文档 20**。

```
evacuate(rt, collection_set):    // STW 版本（基线）
    // collection_set = 选中的低存活率 region 列表
    pause_mutators()

    for region in collection_set:
        for each live_obj in region:
            new_obj = copy_to_free_region(live_obj)
            forwarding[live_obj] = new_obj

    // 更新所有引用
    update_roots_and_slots(forwarding)

    // 释放 collection_set 中的 region
    for region in collection_set:
        gc_region_reset(region)

    resume_mutators()
```

### F.5 前置条件

此算法**不应在 Phase 5 之前尝试实现**。需要以下 substrate 全部稳定：
- region/page 分配器
- mark bitmap（per-region）
- card table / remembered set（cross-region）
- SATB barrier
- safepoint / STW 协调
- 并发线程调度

## 算法复杂度总结

| 算法 | 分配 | 回收触发 | 暂停时间 | 碎片 |
|------|------|---------|---------|------|
| Mark-Sweep STW | O(1) malloc | 阈值 | O(heap) | 有 |
| Gen-Copy-MS | O(1) bump | nursery 满 | O(nursery_live) | young 无 / old 有 |
| Gen-Copy-Compact | O(1) bump | 同上 + old 碎片阈值 | O(old_live) | 无 |
| RC + Cycle | O(1) malloc | rc==0 即时 / purple 满 | O(cycle_subgraph) | 有 |
| Incremental MS | O(1) malloc | 分配 N 字节后步进 | O(budget) 每步 | 有 |
| Regional Concurrent | O(1) bump | 堆占用率 | 初始+最终标记很短 | 无（evacuate） |
