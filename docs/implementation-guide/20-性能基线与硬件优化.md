# 20 — 性能基线、回归门禁与硬件级优化

> "超高速"不是口号,是可度量、可防退化的工程目标。本文件定义性能基线的建立、CI 回归门禁,以及文档 07 之上的硬件级极致优化。

---

## 1. 性能基线体系

### 1.1 基线指标(每个算法、每个 workload)

| 指标 | 单位 | 测量点 |
|------|------|--------|
| alloc_throughput | obj/sec | 纯分配循环 |
| alloc_latency_p50/p99 | ns | 单次分配延迟分布 |
| store_ref_latency | ns | 写屏障开销 |
| minor_pause_p50/p99 | µs | minor GC 暂停 |
| full_pause_p50/p99 | ms | full GC 暂停 |
| mark_throughput | obj/sec 或 MB/sec | 标记速率 |
| sweep_throughput | obj/sec | 清扫速率 |
| peak_rss | MB | 峰值物理内存 |
| heap_overhead | live_bytes / rss | 内存效率 |
| fragmentation | 1 - largest_free/total_free | 碎片率 |

### 1.2 基线文件格式

```
bench/baselines/gen_copy_ms.json
{
  "algorithm": "gen_copy_ms",
  "commit": "abc123",
  "date": "2026-06-08",
  "cpu": "Intel i7-...",
  "results": {
    "alloc_small":       { "ops_per_sec": 120000000, "tolerance_pct": 5 },
    "old_to_young":      { "ns_per_store": 12.3,      "tolerance_pct": 10 },
    "full_collect_graph":{ "pause_ms_p99": 8.2,       "tolerance_pct": 15 }
  }
}
```

### 1.3 建立基线的流程

```bash
# 1. 在性能稳定的机器上,Release 构建
cmake -B build-rel -DCMAKE_BUILD_TYPE=Release -DENABLE_BENCHMARKS=ON -DGC_ALGORITHM=gen_copy_ms
cmake --build build-rel

# 2. 多次运行取中位数（消除噪声）
for i in $(seq 1 10); do ./build-rel/bench/bench_alloc_small; done | bench/collect_median.sh

# 3. 写入 baselines/
./bench/update_baseline.sh gen_copy_ms
```

## 2. CI 性能回归门禁

### 2.1 门禁逻辑

```
对每个 benchmark:
  实测值 = run_benchmark()
  基线值 = read_baseline()
  容差   = baseline.tolerance_pct
  if 实测比基线差超过容差:
      CI 失败,报告 "性能退化: X 从 A 变为 B (-Y%)"
```

### 2.2 门禁脚本

```bash
# bench/check_regression.sh
#!/bin/bash
ALGO=$1
BASELINE="bench/baselines/${ALGO}.json"
for bench in alloc_small old_to_young full_collect_graph; do
    actual=$(./build-rel/bench/bench_${bench} | grep ops_per_sec | cut -d= -f2)
    baseline=$(jq ".results.${bench}.ops_per_sec" $BASELINE)
    tolerance=$(jq ".results.${bench}.tolerance_pct" $BASELINE)
    # 计算退化百分比,超过容差则 exit 1
    regression=$(echo "scale=2; (1 - $actual/$baseline)*100" | bc)
    if (( $(echo "$regression > $tolerance" | bc) )); then
        echo "FAIL: $bench 退化 ${regression}% (容差 ${tolerance}%)"
        exit 1
    fi
done
```

### 2.3 容差设定原则

| benchmark 类型 | 容差 | 理由 |
|---------------|------|------|
| 吞吐量(alloc) | 5% | 稳定,噪声小 |
| 写屏障延迟 | 10% | 受 cache 影响 |
| 暂停时间 | 15% | 受系统调度影响,噪声大 |
| RSS | 5% | 确定性强 |

## 3. 硬件级优化(文档 07 的延伸)

### 3.1 指针压缩(Compressed OOPs)

64 位系统上指针占 8 字节。如果堆 < 32GB,可用 32 位压缩指针(× 8 缩放)表示,对象头从 8 字节压到 4 字节。

```c
/* 压缩指针:存 (addr - heap_base) >> 3,32 位 */
typedef uint32_t gc_cref;  /* compressed reference */

static inline gc_cref gc_compress(gc_runtime* rt, gc_header* obj) {
    if (!obj) return 0;
    return (gc_cref)(((uintptr_t)obj - rt->heap_base) >> 3);
}
static inline gc_header* gc_decompress(gc_runtime* rt, gc_cref cref) {
    if (!cref) return NULL;
    return (gc_header*)(rt->heap_base + ((uintptr_t)cref << 3));
}
```

**收益**:对象头减半,cache 利用率翻倍。**代价**:每次解引用多一次加法+移位。**适用**:堆 < 32GB 且对象引用密集。

### 3.2 Tagged Pointer(小整数内联)

VM 中大量小整数/布尔不需要堆对象。用指针低位 tag 区分:

```c
#define GC_TAG_MASK   0x7
#define GC_TAG_OBJECT 0x0   /* 真指针,8 字节对齐,低 3 位为 0 */
#define GC_TAG_INT    0x1   /* 内联整数 */

static inline int gc_is_object(void* p) {
    return ((uintptr_t)p & GC_TAG_MASK) == GC_TAG_OBJECT;
}
/* trace_slots 中跳过 tagged 非对象值,不当作引用 */
```

**收益**:小整数零分配、零 GC 压力。**约束**:descriptor 的 trace_slots 必须用 `gc_is_object` 过滤。

### 3.3 缓存行对齐与 false sharing

```c
/* 多线程热数据按 cache line（64B）对齐,避免伪共享 */
struct gc_thread_context {
    /* ... 冷数据 ... */
    _Alignas(64) struct {
        uint8_t* tlab_base;
        size_t   tlab_used;
        size_t   tlab_capacity;
    } hot;  /* 独占一条 cache line */
};
```

### 3.4 NUMA 感知分配

多 socket 机器上,内存访问跨 NUMA 节点慢 2-3 倍:

```c
/* 每个线程的 TLAB 从本 NUMA 节点分配内存 */
#ifdef GC_NUMA_AWARE
void* gc_numa_alloc(int node, size_t size) {
    return numa_alloc_onnode(size, node);  /* libnuma */
}
#endif
```

**收益**:多 socket 上分配/访问局部性。**代价**:依赖 libnuma,复杂度高。**优先级**:P3(仅大型服务器)。

### 3.5 SIMD 加速位图扫描

mark bitmap 的清零、查找置位 card 可用 SIMD 批量处理:

```c
/* 用 AVX2 一次检查 256 个 card 是否有脏 */
#ifdef __AVX2__
#include <immintrin.h>
static int has_dirty_card_simd(const uint8_t* bitmap, size_t bytes) {
    for (size_t i = 0; i + 32 <= bytes; i += 32) {
        __m256i v = _mm256_loadu_si256((const __m256i*)(bitmap + i));
        if (!_mm256_testz_si256(v, v)) return 1;  /* 有非零位 */
    }
    return 0;
}
#endif
```

**收益**:大堆的 card 扫描加速 8-32 倍。**约束**:运行时检测 CPU 特性,提供标量 fallback。

### 3.6 预取(Prefetch)

```c
/* 标记时预取下一个对象,隐藏 cache miss 延迟 */
while ((obj = gc_worklist_pop(&wl))) {
    if (wl.top > 0)
        __builtin_prefetch(wl.data[wl.top - 1], 0, 1);
    trace_slots(obj, mark_cb, &ctx);
}
```

### 3.7 分支预测提示

```c
#define GC_LIKELY(x)   __builtin_expect(!!(x), 1)
#define GC_UNLIKELY(x) __builtin_expect(!!(x), 0)

/* 分配快路径:大概率 TLAB 命中 */
if (GC_LIKELY(thread->tlab_used + size <= thread->tlab_capacity)) {
    /* 快路径 */
} else {
    /* 慢路径:refill TLAB / 触发 GC */
}
```

## 4. 硬件优化优先级矩阵

| 优化 | 收益 | 复杂度 | 优先级 | 适用 |
|------|------|--------|--------|------|
| 分支预测提示 | 5-10% 热路径 | 极低 | P1 | 所有 |
| 预取 | 标记 ~20% | 低 | P2 | tracing |
| 缓存行对齐 | 多线程伪共享消除 | 低 | P1 | 多线程 |
| tagged pointer | 小整数零分配 | 中 | P2 | VM 数值密集 |
| 指针压缩 | 对象头减半 | 中 | P3 | 引用密集 + 堆<32G |
| SIMD card 扫描 | card 扫描 8-32x | 中 | P3 | 大堆 |
| NUMA 感知 | 多 socket 局部性 | 高 | P3 | 大型服务器 |

## 6. 超高速实现的检查清单

```
分配路径:
  □ TLAB 命中走 bump-pointer（3 条指令）
  □ 快路径有 GC_LIKELY 提示
  □ 慢路径（refill/GC）不内联,不污染快路径 icache

写屏障:
  □ 条件式（大部分写入提前 return）
  □ card 标脏非原子（多标无害）
  □ 无分支的快速 reject（owner 在 young 直接返回）

标记:
  □ 显式 worklist 不递归
  □ 预取下一对象
  □ mark bit 用 side bitmap（不污染对象 cache line）

多线程:
  □ 热数据 cache line 对齐
  □ 每线程独立 TLAB + 局部 worklist
  □ work-stealing 负载均衡
  □ 全局结构 CAS 或批量提交,不用大锁

内存:
  □ 对象头尽可能小（4-8 字节）
  □ 考虑 tagged pointer 消除小对象
  □ nursery 连续分配保证局部性
```
