# 11 — VM 集成指南

> 本文件是 VM 开发者将自己的解释器/运行时接入 xgc 的完整操作手册。

---

## 1. 集成总览

VM 需要做 5 件事：
1. 定义对象类型的 `gc_descriptor`
2. 实现 `scan_roots` 回调
3. 所有堆字段写入走 `gc_store_ref`
4. 对象分配走 `gc_alloc_typed`
5. 适时触发 `gc_collect_minor` / `gc_collect_full`

---

## 2. Step 1: 定义 Descriptor

每种 VM 对象类型需要一个 `gc_descriptor`：

```c
// 示例：脚本语言中的 Dict 对象
typedef struct VmDict {
    gc_header    gc;           // ← 必须是第一个成员
    VmPair*      pairs;        // 非 GC 管理的数组（malloc 的）
    int          count;
    int          capacity;
} VmDict;

static void dict_trace_slots(gc_header* obj, gc_visit_slot_fn visit, void* ctx) {
    VmDict* d = (VmDict*)obj;
    for (int i = 0; i < d->count; i++) {
        if (d->pairs[i].value_is_object) {
            visit((gc_header**)&d->pairs[i].value, ctx);
        }
    }
}

static void dict_trace_slots_range(gc_header* obj, size_t begin, size_t end,
                                   gc_visit_slot_fn visit, void* ctx) {
    // 如果 pairs 数组很大，可以只扫描 [begin, end) 覆盖的部分
    // 简单实现可直接调用 dict_trace_slots（全量扫描）
    (void)begin; (void)end;
    dict_trace_slots(obj, visit, ctx);
}

static void dict_finalize(gc_header* obj) {
    VmDict* d = (VmDict*)obj;
    free(d->pairs);  // 释放非 GC 管理的资源
}

static const gc_descriptor VM_DICT_DESC = {
    .name              = "Dict",
    .fixed_size        = sizeof(VmDict),
    .flags             = GC_DESC_FLAG_CONTAINS_REFS | GC_DESC_FLAG_HAS_FINALIZER,
    .kind              = 1,
    .trace_slots       = dict_trace_slots,
    .trace_slots_range = dict_trace_slots_range,
    .trace_edges       = NULL,  // 可选
    .finalize          = dict_finalize,
};
```

### Descriptor 规则

| 规则 | 违反后果 |
|------|---------|
| `gc_header` 必须是第一个成员 | 指针转换失败 |
| `trace_slots` 必须覆盖所有引用字段 | GC 漏标 → 活对象被释放 |
| `finalize` 只释放非 GC 资源 | GC 管理的资源由 GC 回收 |
| `trace_slots` 中**不要**追踪非 GC 指针 | slot 可能被 GC 覆写 |
| `fixed_size` 必须 ≥ `sizeof(gc_header)` | 分配时校验失败 |

## 3. Step 2: 实现 Root Scanning

```c
typedef struct VmState {
    VmFrame*  call_stack;
    int       frame_count;
    VmDict*   global_env;
    // ...
} VmState;

static void vm_scan_roots(void* vm_ctx, gc_visit_slot_fn visit, void* ctx) {
    VmState* vm = (VmState*)vm_ctx;

    // 扫描调用栈中的每一帧
    for (int f = 0; f < vm->frame_count; f++) {
        VmFrame* frame = &vm->call_stack[f];
        for (int r = 0; r < frame->local_count; r++) {
            if (frame->locals[r].is_object) {
                visit((gc_header**)&frame->locals[r].as_obj, ctx);
            }
        }
    }

    // 扫描全局环境
    if (vm->global_env) {
        visit((gc_header**)&vm->global_env, ctx);
    }

    // 扫描挂起的协程（如果有）
    for (int c = 0; c < vm->coroutine_count; c++) {
        vm_scan_coroutine_roots(vm->coroutines[c], visit, ctx);
    }
}
```

### Root Scanning 规则

| 规则 | 违反后果 |
|------|---------|
| 必须覆盖所有持有 GC 对象引用的 slot | 漏标 → 活对象被回收 → crash |
| 传递的是 `gc_header**`（slot 地址），不是 `gc_header*`（对象地址） | moving GC 无法更新根引用 |
| 挂起协程的栈也必须扫描 | 协程中的活对象被回收 |
| 不要在 scan_roots 中调用 gc_alloc_typed | 可能触发递归 GC |

## 4. Step 3: 堆字段赋值

```c
// ✅ 正确：
void vm_dict_set(gc_runtime* rt, gc_thread_context* thread,
                 VmDict* dict, int index, VmObject* value) {
    gc_store_ref(rt, thread,
        (gc_header*)dict,                       // owner
        (gc_header**)&dict->pairs[index].value, // slot
        (gc_header*)value);                     // new_value
}

// ❌ 错误：
dict->pairs[index].value = value;  // 绕过写屏障 → remembered set 丢失
```

## 5. Step 4: 对象分配

```c
VmDict* vm_create_dict(gc_runtime* rt, gc_thread_context* thread) {
    VmDict* d = (VmDict*)gc_alloc_typed(rt, thread, &VM_DICT_DESC,
                                         sizeof(VmDict), GC_ALLOC_DEFAULT);
    if (!d) return NULL;  // OOM
    d->pairs = malloc(16 * sizeof(VmPair));
    d->capacity = 16;
    d->count = 0;
    return d;
}
```

### 分配注意事项

- `gc_alloc_typed` 可能触发 minor GC → 所有之前的 root 引用可能已经移动
- 如果要在分配后保持引用，要么放入 root 中，要么用 `gc_handle_acquire` 固定

## 6. Step 5: GC 触发策略

```c
// 方式 A：在解释循环中定期检查
void vm_interpreter_loop(gc_runtime* rt, gc_thread_context* thread) {
    while (running) {
        GC_SAFEPOINT_POLL(rt, thread);  // 多线程时检查 STW
        execute_one_instruction(thread);
        // 分配时 nursery 满了会自动触发 minor GC
    }
}

// 方式 B：在分配失败时显式触发
VmObject* vm_alloc_with_retry(gc_runtime* rt, gc_thread_context* thread,
                              const gc_descriptor* desc, size_t size) {
    VmObject* obj = gc_alloc_typed(rt, thread, desc, size, 0);
    if (!obj) {
        gc_collect_minor(rt);
        obj = gc_alloc_typed(rt, thread, desc, size, 0);
    }
    if (!obj) {
        gc_collect_full(rt);
        obj = gc_alloc_typed(rt, thread, desc, size, 0);
    }
    return obj;  // 可能仍为 NULL → OOM
}
```

## 7. Step 6: Handle/Pin（外部 C 引用保护）

```c
// 场景：C 函数临时持有 GC 对象，期间可能触发 GC
void vm_c_function(gc_runtime* rt, gc_thread_context* thread) {
    VmDict* dict = vm_create_dict(rt, thread);

    // 获取 handle — 防止 dict 在后续 GC 中被移动或回收
    gc_handle* h = gc_handle_acquire(rt, (gc_header*)dict, GC_HANDLE_PINNED);

    // 此处可能触发 GC（dict 的地址可能变化，但 handle 保护它）
    vm_alloc_something_else(rt, thread);

    // 通过 handle 获取最新地址
    dict = (VmDict*)gc_handle_get(h);

    gc_handle_release(h);
}
```

## 8. 集成 Checklist

```
□ 每种对象类型有对应的 gc_descriptor
□ gc_header 是所有 GC 管理对象的第一个成员
□ trace_slots 覆盖所有引用类型字段
□ scan_roots 覆盖栈、全局、协程、寄存器所有根
□ 所有堆字段写入经过 gc_store_ref
□ 非 GC 管理的资源在 finalize 中释放
□ 外部 C 持有 GC 对象时使用 handle/pin
□ 多线程场景下每个 OS 线程都 attach/detach
□ 解释器循环中插入了 GC_SAFEPOINT_POLL（多线程）
□ 大对象使用 GC_ALLOC_PINNED 标记
```

## 9. 常见错误与诊断

| 症状 | 可能原因 | 排查方法 |
|------|---------|---------|
| use-after-free | trace_slots 漏了某个字段 | ASan + GC_DEBUG dump |
| 对象"消失" | scan_roots 没覆盖某个根 | 在 collect 前后 dump 对象链表 |
| 指针失效（非崩溃但值错误） | 对象被移动但引用未更新 | 检查是否绕过了 gc_store_ref |
| 内存只增不减 | finalize 未释放内部 malloc | 检查 descriptor.finalize |
| GC 卡死 | safepoint poll 缺失 → 某线程不响应 STW | 检查解释循环是否有轮询 |
