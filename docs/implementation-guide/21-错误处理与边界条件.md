# 21 — 错误处理与边界条件

> 工业级 GC 的健壮性 80% 体现在边界处理。本文件规定 xgc 所有函数遇到异常输入时的**确定性行为**。低能力 AI 必须严格遵守，不要自己决定如何处理 NULL/OOM/溢出。

---

## 1. 错误处理总原则

xgc 是纯 C 库，**不使用异常、不使用 errno、不使用全局错误状态**。错误通过三种方式表达：

| 方式 | 适用 | 示例 |
|------|------|------|
| 返回值 | 可能失败的操作 | `gc_alloc_typed` 返回 NULL = OOM |
| 返回码 | 校验/操作成功与否 | `gc_*_check_invariants` 返回 0/1 |
| no-op | NULL 输入等"宽容"场景 | `gc_worklist_push(NULL, ...)` 静默返回 |

**绝对禁止**：遇到错误 `abort()`（除非是 `GC_DEBUG` 模式的 invariant panic）。

---

## 2. NULL 参数处理规约

每个公共函数对 NULL 的处理是**确定的**，下表是契约：

| 函数 | NULL 参数 | 行为 |
|------|----------|------|
| `gc_runtime_create` | cfg=NULL | 使用全默认配置 |
| `gc_runtime_create` | algo=NULL | 使用 `xgc_default_algorithm()` |
| `gc_runtime_create` | hooks=NULL | scan_roots 为空（仅 handle 作为根） |
| `gc_runtime_destroy` | rt=NULL | no-op |
| `gc_alloc_typed` | rt=NULL | 返回 NULL |
| `gc_alloc_typed` | desc=NULL | 返回 NULL |
| `gc_alloc_typed` | size < sizeof(gc_header) | 返回 NULL |
| `gc_store_ref` | rt=NULL | no-op |
| `gc_store_ref` | slot=NULL | no-op |
| `gc_store_ref` | new_value=NULL | 合法（清空字段） |
| `gc_store_ref` | owner=NULL | 合法（根级写入，不触发分代屏障） |
| `gc_collect_*` | rt=NULL | no-op |
| `gc_handle_acquire` | rt/obj=NULL | 返回 NULL |
| `gc_handle_release` | handle=NULL | no-op |
| `gc_worklist_push` | wl/obj=NULL | no-op |
| `gc_worklist_pop` | wl=NULL 或空 | 返回 NULL |

**实现模板**（每个公共函数开头）：
```c
void gc_some_func(gc_runtime* rt, ...) {
    if (rt == NULL) return;            /* 或 return NULL; */
    ...
}
```

## 3. OOM（内存耗尽）处理

### 3.1 分配路径 OOM

```c
void* gc_alloc_typed(...) {
    /* 1. 尝试算法 alloc */
    void* obj = algo->alloc(...);
    if (obj) return obj;

    /* 2. 算法 alloc 失败 → 触发 GC 后重试 */
    gc_collect_minor(rt);
    obj = algo->alloc(...);
    if (obj) return obj;

    /* 3. 再次失败 → full GC 后重试 */
    gc_collect_full(rt);
    obj = algo->alloc(...);
    if (obj) return obj;

    /* 4. 仍然失败 → 通知 VM，返回 NULL */
    if (rt->hooks.on_oom) rt->hooks.on_oom(rt->hooks.vm_ctx);
    return NULL;
}
```

> **注意**：当前 baseline 的 `gc_alloc_typed` 没有 retry 逻辑（直接 fallback calloc）。实现 retry 是 Step E（arena）的一部分。

### 3.2 内部数据结构 OOM（worklist/forwarding/card_table）

| 结构 | OOM 时行为 |
|------|-----------|
| worklist realloc 失败 | **不能丢对象**！必须有保底策略：用固定大小溢出缓冲或标记"需要全量重扫" |
| forwarding insert 失败 | 当前对象不移动（保守保留在原地），记录错误 |
| card_table register 失败 | 该 owner 标记为"全脏"（保守，下次全扫） |

**关键原则**：内部 OOM 时**宁可保守（多保留对象、多扫描）也不能漏掉活对象**。

### 3.3 worklist OOM 的保底实现

```c
void gc_worklist_push(gc_worklist* wl, gc_header* obj) {
    if (!wl || !obj) return;
    if (wl->top < wl->capacity) {
        wl->data[wl->top++] = obj;
        return;
    }
    /* 扩容 */
    int new_cap = wl->capacity > 0 ? wl->capacity * 2 : 16;
    gc_header** new_data = realloc(wl->data, (size_t)new_cap * sizeof(gc_header*));
    if (!new_data) {
        /* OOM 保底：设置溢出标志，GC 结束后需要全量重扫 */
        wl->overflow = 1;   /* 需要在 gc_worklist 结构中增加此字段 */
        return;             /* 丢弃本次 push，但记录了溢出 */
    }
    wl->data = new_data;
    wl->capacity = new_cap;
    wl->data[wl->top++] = obj;
}
```

> mark 阶段结束后，如果 `wl->overflow == 1`，必须从头再扫一遍全堆（保守但正确）。

## 4. 整数溢出防护

| 场景 | 风险 | 防护 |
|------|------|------|
| `size + align` | 溢出回绕 → 分配过小 | 先检查 `size > SIZE_MAX - align` |
| `bit_count + 7` | 溢出 | 检查 `bit_count > SIZE_MAX - 7` |
| `capacity * 2` | 溢出 | 检查 `capacity > INT_MAX / 2` |
| `total_allocated += size` | 累加溢出 | 实际中 64 位很难溢出，但 dec 时要 floor 0 |

**对齐溢出检查模板**：
```c
static inline size_t gc_align_up_checked(size_t n, size_t align, int* overflow) {
    if (n > SIZE_MAX - (align - 1)) { *overflow = 1; return 0; }
    return (n + align - 1) & ~(align - 1);
}
```

## 5. 重入防护

| 场景 | 风险 | 防护 |
|------|------|------|
| finalize 中调 gc_alloc | 递归触发 GC | finalize 期间设 `rt->in_finalize` 标志，禁止 GC |
| scan_roots 中调 gc_collect | 无限递归 | 同上，设 `rt->in_collection` 标志 |
| write_barrier 中触发 GC | RC release 链过深 | 用 worklist 迭代，不递归 |

**重入标志实现**：
```c
/* gc_runtime 增加字段 */
struct gc_runtime {
    ...
    int in_collection;   /* 正在 GC 中 */
    int in_finalize;     /* 正在执行 finalizer */
};

void gc_collect_full(gc_runtime* rt) {
    if (!rt || rt->in_collection) return;   /* 防止重入 */
    rt->in_collection = 1;
    ...
    rt->in_collection = 0;
}
```

## 6. 边界条件清单

| 边界 | 必须正确处理 |
|------|-------------|
| 空堆 GC | 没有对象时 collect 不崩溃 |
| 单对象自环 A→A | RC/tracing 都要正确回收 |
| 全部对象都存活 | sweep 阶段不释放任何对象 |
| 全部对象都死亡 | sweep 释放所有，链表变空 |
| nursery 容量为 0 | 所有对象直接进 old |
| 对象 size 恰好等于 nursery 容量 | 边界分配 |
| descriptor 的 trace_slots 为 NULL | 视为无引用对象（叶子节点） |
| descriptor 的 finalize 为 NULL | 跳过 finalize 直接释放 |
| handle 指向已被其他路径释放的对象 | **不应发生** — handle 应保护对象，是 bug |
| GC 期间 mutator 修改对象图（多线程） | 写屏障维护不变式 |

## 7. 断言 vs 错误返回的边界

```
用 GC_ASSERT（仅 Debug 生效）的场景：
  - "永远不应该发生"的内部不变式违反
  - 例如：sweep 后 total_allocated 为负

用错误返回的场景：
  - 调用方可能传入的非法输入
  - 例如：gc_alloc_typed 的 size 太小

用 no-op 的场景：
  - NULL 等可宽容的输入
  - 例如：gc_worklist_push(NULL, ...)
```
