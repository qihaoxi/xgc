# 20 — 并发重定位、读屏障与指针染色

> **本文档是"超高速"卖点的核心机制。** 05.F 的 Regional Concurrent Collector 的疏散阶段目前是 STW（停顿与存活集大小成正比）。要做到 **亚毫秒、与堆大小解耦的停顿**（ZGC / Shenandoah 级别），必须让对象在被移动的同时，mutator 还能并发读写它。本文档给出可实现的机制。
>
> **前置依赖**：必须先完成 05.F 的并发标记、16 的内存模型、19 的屏障内联契约。本机制属于 Phase 5 之后的高级目标，**不是 MVP**。低能力 AI 若未完成前置算法，**不要**尝试本文档。

---

## 1. 问题：移动对象时 mutator 在读它

STW 疏散之所以简单，是因为"复制对象"和"更新所有引用"之间没有 mutator 介入。一旦并发：

```
时刻 T0: collector 把 obj 从 A 复制到 B（A、B 内容暂时相同）
时刻 T1: mutator 读字段 x = obj->field（它读的是 A 还是 B？）
时刻 T2: collector 更新某个引用 ptr = B
时刻 T3: 另一个 mutator 通过尚未更新的引用读到 A，写 A->field = v
         → 这个写丢失了（B 不会看到）
```

核心矛盾：**复制和引用更新无法原子完成**，中间窗口里存在 A、B 两个副本。解决思路只有一个方向——**让所有访问都被引导到唯一权威副本**，这就需要**读屏障（load barrier）**。

---

## 2. 三种读屏障对比（选型）

| 方案 | 机制 | 读开销 | 内存开销 | 代表 | xgc 选型 |
|------|------|--------|----------|------|----------|
| **Brooks forwarding pointer** | 每个对象头部多一个 `forwarding` 槽，永远指向"当前副本"（未移动时指向自己）。读对象前先解引用 forwarding | 每次读 +1 间接 | 每对象 +1 指针 | 早期 Shenandoah | 备选 |
| **Baker read barrier** | 读引用时检查目标是否在 from-space，是则触发复制并更新引用 | 条件分支 + 偶发复制 | 无额外头 | 早期增量复制 | 不选（复制时机不可控）|
| **Load-Value Barrier（LVB）+ 染色指针** | 引用值里嵌入颜色位；读引用时检查颜色，"坏色"则自愈（self-healing）为新地址并修正槽 | 一次位测试 + 偶发慢路径 | 无额外头（用指针高位）| ZGC / 现代 Shenandoah | **首选** |

**xgc 决策**：旗舰并发算法用 **LVB + 染色指针**（无对象头开销、可内联、停顿与堆解耦）。资源受限或不愿动指针位的平台，回退到 **Brooks forwarding pointer**（实现简单，正确性容易论证）。两者都封装在 `gc_read_ref()` facade 之下，算法对 VM 暴露的接口不变。

## 3. 染色指针（Colored Pointers）

### 3.1 位布局

64 位平台用户态地址通常只用低 48 位（x86-64）或 48/52 位（AArch64）。把高位拿来存颜色：

```c
// 以 ZGC 风格的"元数据位在低位之上"或"高位染色"二选一。
// xgc 采用高位染色（地址对齐到 region，低位也可复用，但高位更通用）。

// 假设有效地址 44 位（16TB 堆上限，足够），bit[44..47] 存颜色：
#define GC_ADDR_BITS      44
#define GC_ADDR_MASK      ((1ULL << GC_ADDR_BITS) - 1)        // 取出真实地址
#define GC_COLOR_SHIFT    GC_ADDR_BITS
#define GC_COLOR_MASK     (0xFULL << GC_COLOR_SHIFT)          // 4 个颜色位

// 颜色位语义（同一时刻只有一个 "good" 颜色，其余为 "bad"）：
enum {
    GC_COLOR_MARKED0  = 1ULL << (GC_COLOR_SHIFT + 0),  // 本轮已标记（偶数轮）
    GC_COLOR_MARKED1  = 1ULL << (GC_COLOR_SHIFT + 1),  // 本轮已标记（奇数轮）
    GC_COLOR_REMAPPED = 1ULL << (GC_COLOR_SHIFT + 2),  // 已指向重定位后的地址
    GC_COLOR_FINALIZE = 1ULL << (GC_COLOR_SHIFT + 3),  // 仅 finalizable 可达
};
```

> **MARKED0/MARKED1 交替**：每轮 GC 切换"哪个 mark 位是 good"，避免每轮清除全部对象颜色（一个 epoch 翻转 O(1) 代替 O(heap)）。

### 3.2 地址解码

```c
static inline gc_header* gc_ptr_addr(uintptr_t colored) {
    return (gc_header*)(colored & GC_ADDR_MASK);
}
static inline uint64_t gc_ptr_color(uintptr_t colored) {
    return colored & GC_COLOR_MASK;
}
```

### 3.3 "好色" / "坏色"

GC 维护一个全局 `gc_good_color`（当前 epoch 期望的颜色组合）。读到的引用若颜色 == good，快路径直接用；否则进慢路径自愈。

```c
extern uintptr_t gc_good_color;   // 由 collector 在 phase 切换时更新

static inline int gc_color_is_good(uintptr_t colored) {
    return (colored & GC_COLOR_MASK) == gc_good_color;
}
```

> **硬件加速**：x86-64 可用未使用高位 + `TEST` 单指令；某些平台用 `MOV` 到段寄存器 trick。AArch64 的 Top-Byte-Ignore（TBI）特性允许地址高 8 位被 CPU 自动忽略，染色指针可直接解引用而无需先清位——这是 AArch64 上染色指针几乎零开销的关键。详见 §8。

## 4. Load-Value Barrier（读屏障快慢路径）

### 4.1 facade 接口（VM/算法都通过它读堆引用）

```c
// gc_internal.h
gc_header* gc_read_ref(gc_header** slot);   // 读屏障入口
```

非并发算法（Mark-Sweep / Gen-Copy STW）里 `gc_read_ref` 直接 `return *slot;`（编译期消除，零开销）。并发重定位算法里它是 LVB。

### 4.2 快路径（可内联，JIT 也内联这段——见文档 19 契约 C 的对称形式）

```c
static inline gc_header* gc_read_ref(gc_header** slot) {
    uintptr_t v = (uintptr_t)*slot;
    if (__builtin_expect(v == 0, 0)) return NULL;
    if (__builtin_expect(gc_color_is_good(v), 1)) {
        return gc_ptr_addr(v);                  // 快路径：颜色对，直接用
    }
    return gc_read_ref_slow(slot, v);           // 慢路径：自愈
}
```

### 4.3 慢路径（self-healing）

```c
gc_header* gc_read_ref_slow(gc_header** slot, uintptr_t bad) {
    gc_header* obj = gc_ptr_addr(bad);

    // 1. 若处于 relocate 阶段且 obj 在 collection set 中：确保它已被复制
    if (gc_in_collection_set(obj)) {
        gc_header* to = gc_forward(obj);        // 已复制则取 forwarding；否则现在就复制
        obj = to;
    }
    // 2. 用 good color 重新染色，写回 slot（self-healing：下次读走快路径）
    uintptr_t healed = (uintptr_t)obj | gc_good_color;
    //   CAS 写回，避免覆盖其他线程已写入的更新值
    gc_cas_ref(slot, bad, healed);
    return obj;
}
```

关键点：
- **self-healing 把修正成本摊销**：第一个读到坏色的线程修复 slot，后续读全走快路径。引用更新因此**不需要一次性 STW 扫描全堆**——它是 lazy、并发、分摊的。
- `gc_forward` 用 CAS 安装 forwarding，保证多线程同时复制同一对象时只有一个胜出（见 §5.2）。

## 5. 并发重定位（relocate / remap 两阶段）

把 05.F 的 STW `evacuate` 替换为并发版本。分两个逻辑阶段，二者都可在 mutator 运行时进行：

### 5.1 阶段 Relocate（并发复制）

```
relocate(collection_set):
    翻转 epoch：gc_good_color 现在要求 REMAPPED 位
    for region in collection_set (并行, work-stealing):
        for live_obj in region:
            gc_forward(live_obj)        // 复制（若 mutator 已通过读屏障复制过则跳过）
    // 注意：此阶段结束时，引用仍可能指向旧地址（坏色），靠读屏障 lazy 修正
```

### 5.2 `gc_forward`：竞争安全的复制

```c
gc_header* gc_forward(gc_header* from) {
    // forwarding word 存放在 from-space 对象的第一个字（对象已死，可复用）
    uintptr_t fwd = gc_atomic_load(&from->_fwd, memory_order_acquire);
    if (fwd & GC_FWD_INSTALLED) {
        return (gc_header*)(fwd & ~GC_FWD_INSTALLED);   // 已被别人复制
    }
    // 尝试复制
    gc_header* to = gc_region_alloc(target_region, from->size);
    memcpy(to, from, from->size);
    uintptr_t desired = (uintptr_t)to | GC_FWD_INSTALLED;
    uintptr_t expected = fwd;
    if (gc_atomic_cas(&from->_fwd, &expected, desired,
                      memory_order_release, memory_order_acquire)) {
        return to;                       // 我赢了
    }
    // 别人先复制了：回滚我多分配的 to，用别人的结果
    gc_region_undo_alloc(target_region, to, from->size);
    return (gc_header*)(expected & ~GC_FWD_INSTALLED);
}
```

> **陷阱**：`memcpy` 必须在 CAS **之前**完成，否则赢得 CAS 的线程可能返回一个内容还没拷完的 `to`。`release` 序保证 memcpy 对取到 forwarding 的 acquire 读者可见。

### 5.3 阶段 Remap（并发指针修正）

引用修正**不需要独立的 STW 全堆扫描**——它发生在：
1. **读屏障 self-healing**（mutator 顺带修）；
2. **下一轮并发标记遍历对象图时顺带 remap**（collector 顺带修）。

当下一轮 mark 遍历完成，所有存活引用必然都被读过或被标记过，旧 from-space 即可整体回收。这就是 ZGC "上一轮的 remap 与这一轮的 mark 合并"的核心技巧。

### 5.4 唯一的 STW 点

并发重定位算法里 STW 只剩两个**极短**的点（与堆大小无关，只与根集合大小有关）：
1. **初始标记**：扫描根，翻转 mark 颜色 epoch。
2. **再标记/重定位起点**：处理 SATB 残余、选定 collection set、翻转 remap 颜色 epoch。

目标停顿：**< 1ms**，与堆大小、存活对象数解耦。

## 6. 并发标记的终止检测（Mark Termination）

并行标记有多个 worker，各自有 local mark stack + 全局 work-stealing deque（见文档 07）。**何时判定"全局再无灰色对象"** 是正确性关键——过早判定会漏标。

用 **非阻塞终止检测（Hendler-Shavit / 计数法的简化版）**：

```c
typedef struct {
    _Atomic int active_workers;   // 正在干活的 worker 数
    _Atomic int global_empty;     // 所有共享队列为空的探测标志
} gc_mark_termination;

// worker 主循环
void mark_worker(gc_mark_termination* term) {
    for (;;) {
        gc_header* obj = local_pop();
        if (!obj) obj = steal_from_others();      // work-stealing
        if (!obj) {
            // 本地无活：宣告 idle
            if (atomic_fetch_sub(&term->active_workers, 1) == 1) {
                // 我是最后一个：可能全局完成。做一次"屏障确认"
                if (all_queues_empty()) { signal_done(); return; }
            }
            // 等待新工作或终止信号；有工作则重新 active++
            if (wait_for_work_or_done(term)) return;
            atomic_fetch_add(&term->active_workers, 1);
            continue;
        }
        mark_and_push_children(obj);     // 可能往队列里加新灰色
    }
}
```

关键不变式：**`active_workers == 0` 且所有队列为空** 才算终止。任一 worker 在 idle 后又被 steal 到工作，必须先 `active_workers++` 再处理，防止"最后一个 worker idle → 判定完成 → 其实别人队列里还有货"的竞态。

> SATB 写屏障在并发标记期间持续把"被覆盖的旧引用"压入队列，所以终止检测必须把 SATB buffer 的 drain 也纳入"队列非空"判断。

## 7. Brooks Forwarding Pointer（回退方案）

不愿动指针位的平台用这个。每个对象头部前置一个 forwarding 字：

```c
typedef struct {
    gc_header* forwarding;   // 未移动时 == 自己；移动后指向新副本
    gc_header  header;       // 原 4 字段
    // ... 字段
} GcBrooksObject;

static inline gc_header* gc_read_ref(gc_header** slot) {
    gc_header* obj = *slot;
    if (!obj) return NULL;
    return ((GcBrooksObject*)((char*)obj - offsetof(GcBrooksObject, header)))->forwarding;
}
```

- 复制时：`memcpy` 后把**旧对象**的 `forwarding` 指向新对象。此后任何经旧对象的读都被转发到新副本——**写也必须经 forwarding**（写屏障里先 `obj = obj->forwarding` 再写），否则写丢失。
- 代价：每对象多一个指针（8B）、每次读多一次解引用。
- 优点：正确性极易论证，无指针位魔法，可移植到不支持高位染色的平台。

## 8. 弱内存架构（AArch64 等）的特别注意

x86-64 是 TSO（强序），很多疏漏在 x86 上"碰巧"正确；AArch64/POWER 是弱序，必须严格按文档 16 的内存序：

| 场景 | x86 可侥幸 | AArch64 必须 |
|------|-----------|--------------|
| 发布新对象（先初始化字段后发布引用）| 写写不重排，常侥幸 | 发布引用用 `release`，读引用用 `acquire`/`consume` |
| forwarding 安装 | — | `release`（保证 memcpy 可见）+ 读 `acquire` |
| self-healing CAS 写回 slot | — | `acq_rel` |
| 颜色 epoch 翻转后让所有线程看到 | — | 翻转后必须有全局 fence 或经 safepoint（所有 mutator 过一次 safepoint 即建立 happens-before）|

> **AArch64 福利**：Top-Byte-Ignore（TBI，`TCR_EL1.TBI=1`，Linux 用户态默认开）让 CPU 在访存时自动忽略地址高 8 位。于是染色指针可**直接解引用而无需先 mask 掉颜色位**，读屏障快路径少一条指令。x86-64 无此特性，必须显式 `& GC_ADDR_MASK`（但 `AND` 几乎免费，且常可被 JIT 折叠进寻址模式）。

## 9. 实现优先级与验收

| 优先级 | 项 | 说明 |
|--------|-----|------|
| 必须（启用并发重定位前提）| `gc_read_ref` facade + 非并发零开销特化 | 先让所有算法走 facade，STW 算法编译期消除 |
| 必须 | Brooks forwarding 回退实现 | 正确性基线，先于染色指针 |
| 高 | `gc_forward` 竞争安全复制 + relocate 阶段 | |
| 高 | 并发标记终止检测 | 否则并行标记漏标 |
| 中 | 染色指针 + LVB self-healing | 性能旗舰，AArch64 上收益最大 |
| 中 | remap 与下一轮 mark 合并 | 消除独立 remap STW |

**验收**：
- 在 `-DGC_ALGORITHM=regional` 下，差分测试（文档 17）全过，且 TSan（文档 16）无真报。
- 停顿直方图：STW 段 p99 < 1ms 且**不随堆增长**（用文档 18 的 benchmark 矩阵，分别测 256MB / 4GB / 16GB 堆，p99 停顿应基本持平）。
- 读屏障快路径在 perf 中占比可量化，慢路径触发率随 self-healing 收敛（同一轮内单调下降）。

---

## 10. 一句话总结

**STW 疏散的停顿与存活集成正比；要做到与堆解耦的亚毫秒停顿，必须用读屏障把所有访问引导到权威副本，让引用修正变成 lazy、并发、自愈、可摊销的过程。** 染色指针 + LVB 是高性能首选，Brooks forwarding 是可移植回退，二者都藏在 `gc_read_ref` facade 之后，对 VM 透明。
