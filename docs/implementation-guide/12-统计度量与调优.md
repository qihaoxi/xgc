## 4. 背压（Backpressure）机制

### 4.1 三级压力模型

| 级别 | 条件 | 框架行为 | 建议 VM 行为 |
|------|------|---------|-------------|
| `GC_PRESSURE_NORMAL` (0) | allocated < soft | 仅 minor GC on nursery full | 正常执行 |
| `GC_PRESSURE_MEDIUM` (1) | allocated ≥ soft | 增量回收 / 限速 | 限制分配速率 |
| `GC_PRESSURE_HIGH` (2) | allocated ≥ hard | 强制 full STW GC | GC 后仍超限 → OOM |

**压力等级的枚举与查询函数**（08 §3.2 软引用清除也依赖此定义）：

```c
/* gc_internal.h */
typedef enum {
    GC_PRESSURE_NORMAL = 0,
    GC_PRESSURE_MEDIUM = 1,
    GC_PRESSURE_HIGH   = 2,
} gc_pressure_level;

/* 根据 rt->stats.total_allocated 与 cfg 阈值判定当前压力等级 */
gc_pressure_level gc_current_pressure(const gc_runtime* rt);
```

> 08 §3.2 的 `gc_soft_should_clear` 用的 `gc_pressure_level` / `gc_current_pressure` / `GC_PRESSURE_HIGH` / `GC_PRESSURE_MEDIUM` 就是本节定义的，**不要在 08 另定义**。`on_pressure` 回调（§4.2）的 `level` 参数即此枚举值。

### 4.2 压力通知回调

```c
// gc_vm_hooks 中增加：
typedef struct gc_vm_hooks {
    gc_scan_roots_fn  scan_roots;
    void*             vm_ctx;
    // 新增：
    void (*on_pressure)(void* vm_ctx, gc_pressure_level level);  // 压力变化通知
    void (*on_oom)(void* vm_ctx);                    // 无法恢复的 OOM
} gc_vm_hooks;
```

### 4.3 自适应触发策略

```c
// 每次 GC 后根据存活率调整下次触发阈值
void gc_adjust_trigger_after_collection(gc_runtime* rt) {
    size_t live = rt->stats.heap_live_bytes;
    int growth = rt->cfg.gc_growth_percent;  // 默认 100 (翻倍)
    rt->next_gc_trigger = live + live * growth / 100;
    if (rt->next_gc_trigger > rt->cfg.gc_threshold_hard) {
        rt->next_gc_trigger = rt->cfg.gc_threshold_hard;
    }
}
```

## 5. 堆自适应伸缩与归还 OS

> 长时间运行的常驻进程（服务端）必须能在负载回落后**把空闲堆物理内存还给 OS**，否则进程 RSS 只增不减。这一节是"工业级"与"玩具 GC"的分水岭之一。

### 5.1 自适应堆增长 / 收缩策略

GC 维护一个**目标堆大小**，依据每轮 GC 后的存活量和"目标停顿/吞吐比"动态调整：

```c
typedef struct {
    double  target_utilization;   // 目标存活率，如 0.7：堆 = live / 0.7
    size_t  min_heap;             // 下限（避免频繁 GC）
    size_t  max_heap;             // 上限（硬约束）
    double  grow_factor;          // 一次最多扩多少倍，如 1.5（防抖动）
    double  shrink_factor;        // 一次最多缩多少，如 0.9（缓慢收缩，防来回伸缩）
    uint32_t shrink_after_idle_gcs; // 连续 N 轮低占用才收缩
} gc_heap_policy;

size_t gc_compute_target_heap(gc_runtime* rt) {
    size_t live = rt->stats.heap_live_bytes;
    size_t want = (size_t)(live / rt->policy.target_utilization);

    // 限制单次变化幅度，避免抖动
    size_t cur = rt->heap_committed;
    size_t max_grow   = (size_t)(cur * rt->policy.grow_factor);
    size_t max_shrink = (size_t)(cur * rt->policy.shrink_factor);
    if (want > max_grow)   want = max_grow;
    if (want < max_shrink) want = max_shrink;

    if (want < rt->policy.min_heap) want = rt->policy.min_heap;
    if (want > rt->policy.max_heap) want = rt->policy.max_heap;
    return want;
}
```

**防抖动**是关键：收缩必须**滞后且缓慢**（连续多轮低占用才缩、一次只缩一点），否则负载波动会导致 commit/decommit 频繁系统调用，反而拖慢。

### 5.2 归还物理内存给 OS（保留虚拟地址）

复用文档 10 的 `gc_page_decommit`。**只归还物理页，保留虚拟地址区间**，这样下次扩张无需重新 mmap：

```c
// 平台抽象（文档 10 已声明 gc_page_decommit / gc_page_commit）
void gc_page_decommit(void* ptr, size_t size) {
#if defined(__linux__)
    // MADV_DONTNEED：立即归还物理页，再次访问触发缺页清零（匿名映射）
    madvise(ptr, size, MADV_DONTNEED);
    //   备选 MADV_FREE（更快，但 RSS 在内存压力前不下降）——监控类场景用 DONTNEED
#elif defined(__APPLE__)
    madvise(ptr, size, MADV_FREE);                  // macOS 无 DONTNEED 等价语义
#elif defined(_WIN32)
    VirtualFree(ptr, size, MEM_DECOMMIT);           // 保留地址，释放物理
#endif
}
```

### 5.3 何时收缩（触发点）

```
每轮 GC 结束后：
  target = gc_compute_target_heap(rt)
  if target < heap_committed:
      连续低占用计数++ 
      if 计数 >= policy.shrink_after_idle_gcs:
          把超出 target 的、且已全空的 region/page decommit 还给 OS
          heap_committed = target
          计数清零
  else:
      计数清零
      if target > heap_committed: commit 更多页（按需，惰性）
```

> **moving 算法的优势**：复制/压缩后空闲区是**连续**的，可整段 decommit。non-moving（Mark-Sweep）的空闲是碎片化的，只能整页空闲时才能归还——这也是为什么常驻服务更偏好分代/region 型算法。

### 5.4 与压力回调联动

§4.2 的压力回调里，VM 可主动请求 GC "尽量归还内存"（如容器收到内存告警）：

```c
void gc_request_shrink(gc_runtime* rt, int aggressive);
// aggressive=1：立即做一次 full GC + 压缩 + decommit，牺牲一次停顿换 RSS 下降
```

## 6. Benchmark 基础设施

### 6.1 计时工具

```c
// src/core/clock.c（新建）
#include <time.h>

double gc_clock_now_ms(void) {
    struct timespec ts;
    timespec_get(&ts, TIME_UTC);
    return (double)ts.tv_sec * 1000.0 + (double)ts.tv_nsec / 1000000.0;
}
```

### 6.2 输出格式标准

### 6.3 推荐 benchmark 矩阵

| Benchmark | 度量重点 | 对应优化 |
|-----------|---------|---------|
| `alloc_small` | 小对象分配速率 | bump-pointer / TLAB |
| `alloc_large` | 大对象分配路径 | LOS / malloc |
| `old_to_young_writes` | 写屏障 + minor GC | card_table / barrier |
| `full_collect_graph` | full GC 暂停时间 | mark 效率 / sweep 效率 |
| `nursery_churn` | 短命对象 GC 吞吐 | nursery size / copying |
| `cycle_detection` | 环回收延迟 | trial deletion 效率 |
| `concurrent_alloc` | 多线程分配竞争 | TLAB / 无锁 |
| `promotion_rate` | 晋升压力 | 晋升策略 / old gen 管理 |
