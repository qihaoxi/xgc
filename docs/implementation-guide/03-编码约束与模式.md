# 03 — 编码约束与模式

> 实现过程中必须遵守的所有规则。违反任何一条都可能导致框架正确性或可扩展性退化。

---

## 1. 语言与构建

| 规则 | 说明 |
|------|------|
| C11 标准 | `CMAKE_C_STANDARD 11`，`CMAKE_C_EXTENSIONS OFF` |
| 编译器警告 | `-Wall -Wextra -Wpedantic -Werror -Wstrict-prototypes -Wmissing-declarations` |
| 允许的 GNU 扩展 | 仅 `GC_ATOMIC_XCHG` 宏中的 `__extension__({...})` + `__typeof__` |
| 缩进 | Tab 缩进，4 空格宽度 |
| 行宽 | 120 列 |
| clang-format | 使用仓库根目录 `.clang-format`，所有 `.c`/`.h` 必须格式化 |

## 2. 命名规范

| 类别 | 规则 | 示例 |
|------|------|------|
| 类型 | `snake_case` | `gc_runtime`, `gc_header`, `gc_algorithm_vtable` |
| 函数 | `gc_` 前缀 + `snake_case` | `gc_alloc_typed`, `gc_worklist_push` |
| 宏 | `GC_` 前缀 + `UPPER_SNAKE` | `GC_ATOMIC_LOAD`, `GC_STATE_RUNNING` |
| 内部函数 | `static` + 无 `gc_` 前缀或加算法前缀 | `gc_marksweep_mark_object` (static) |
| 枚举值 | `GC_` 前缀 + `UPPER_SNAKE` | `GC_ALLOC_PINNED`, `GC_COLOR_BLACK` |
| 文件 | `snake_case` | `gc_internal.h`, `card_table.c`, `young_copy.c` |

## 3. 框架层约束

### 3.1 `gc_header` 不可扩展
```c
// 永远只有这 4 个字段：
struct gc_header {
    const gc_descriptor* desc;
    uint32_t             size;
    uint16_t             flags;
    uint16_t             kind;
};
```
**理由**：算法元数据放 side metadata 或 `algo_state`。如果某个算法需要 mark bit / rc / forwarding，用 bitmap 或私有结构体实现。

### 3.2 写屏障不可绕过
```c
// ✅ 正确：
gc_store_ref(rt, thread, owner, (gc_header**)&owner->child, (gc_header*)new_child);

// ❌ 禁止：
owner->child = new_child;  // 跳过了 write_barrier，remembered set 会漏记
```

### 3.3 共享能力下沉规则
```
判断标准：如果未来 2 个以上算法都需要这个能力，放 src/core/
         如果只有一个算法需要，可以暂时放 src/algo/<name>/
         
当前已在 core 的：worklist / bitmap / card_table / barrier / heap / reclaim / descriptor
```

### 3.4 算法私有状态的存放方式
```c
// 全局私有状态：
rt->algo_state = my_private_global_struct;

// 线程私有状态：
thread->algo_state = my_private_thread_struct;

// ❌ 禁止在 gc_header 中附加字段
// ❌ 禁止在 gc_internal.h 中为某算法专门添加字段
```

### 3.5 invariant 验证调用时机
```c
// 每个 substrate 测试中必须调 gc_runtime_check_invariants(rt)
// smoke test 的关键步骤后必须调
// benchmark 中不调（性能开销）
```

## 4. 算法插件约束

### 4.1 vtable 必须声明的函数

| 必须非 NULL | 条件 |
|-------------|------|
| `name` | 始终 |
| `alloc` | 始终 |
| `collect_full` | 始终 |
| `write_barrier` | 当 `caps.requires_write_barrier == 1` |
| `read_barrier` | 当 `caps.requires_read_barrier == 1` |
| `pin` + `unpin` | 当 `caps.supports_moving == 1` |
| `collect_minor` | 当 `caps.supports_generations == 1` |

### 4.2 alloc() 的契约
```c
// alloc 必须：
//   1. 返回的内存至少 sizeof(gc_header) 大
//   2. obj->desc 必须被设置（可以由 alloc 设置，或交给 runtime.c 的 fallback 设置）
//   3. obj->size 必须被设置
//   4. 如果返回 NULL，runtime.c 会 fallback 到 calloc

// alloc 可以：
//   - 决定对象进入哪个 space/generation
//   - 通过 gc_heap_record_young_alloc / gc_heap_record_old_alloc 记账
//   - 触发 minor GC（如 nursery 满了）
```

### 4.3 write_barrier() 的契约
```c
// 调用时 *slot 已经被写入 new_value（runtime.c 先写）
// write_barrier 看到的参数：
//   owner:     包含 slot 的对象
//   slot:      指向字段的指针
//   old_value: slot 之前的值
//   new_value: slot 当前的值（已写入）

// write_barrier 可以：
//   - 调用 gc_barrier_mark_slot_dirty（分代 GC）
//   - 做 RC retain/release（RC 算法）
//   - 做 SATB 记录旧值（并发 GC）
//   - 什么都不做（marksweep）
```

### 4.4 collect_*() 的契约
```c
// collect_minor: 只回收年轻代（快速）
// collect_major: 回收老年代（可先做 minor）
// collect_full:  回收整个堆（所有对象都可能被释放）

// 回收过程中必须：
//   - 通过 hooks.scan_roots 扫描根
//   - 通过 desc->trace_slots 遍历对象引用
//   - 通过 gc_reclaim_object 释放死亡对象
//   - handle 链表中的对象必须被认为存活

// 回收过程中可以：
//   - 使用 worklist（但不拥有它——使用 rt->worklist_data 共享缓冲区）
//   - 调用 gc_barrier_visit_dirty_cards 扫描 remembered set
//   - 移动对象并更新 root slot（如果 caps.supports_moving）
```

## 5. 测试约束

### 5.1 substrate 测试结构
```c
// 每个 substrate 测试是一个独立 main() 程序
// 不依赖任何外部测试框架
// 使用 assert() 验证
// 返回 EXIT_SUCCESS 表示全部通过

#include "gc_internal.h"
#include <assert.h>
#include <stdlib.h>

int main(void) {
    // setup
    // exercise
    // assert
    // teardown
    return EXIT_SUCCESS;
}
```

### 5.2 smoke 测试模板
```c
// 每个算法有一个 smoke test
// 必须覆盖：
//   1. 创建 runtime + attach thread
//   2. 分配对象 + 建立引用关系
//   3. gc_collect 后验证存活/死亡
//   4. handle 持有对象不被回收
//   5. 环引用被正确回收（如果算法支持）
//   6. gc_runtime_check_invariants(rt) == 1 在关键步骤后
//   7. gc_thread_detach + gc_runtime_destroy 清理

// 不使用 gc_alloc_typed 以外的分配方式
// 不直接写 slot（必须通过 gc_store_ref）
```

### 5.3 命名规则
```
tests/test_<substrate>_substrate.c  — substrate 单元测试
tests/test_<algorithm>_smoke.c      — 算法集成测试
```

## 6. 禁止行为清单

| 编号 | 禁止行为 | 理由 |
|------|---------|------|
| F1 | 在 `gc_header` 中增加字段 | 破坏公共对象模型最小化 |
| F2 | 在 `gc_internal.h` 中为单一算法增加类型 | 污染共享内部头 |
| F3 | 算法直接 `free(obj)` 而不经过 `gc_reclaim_object` | 跳过 finalize 和统计 |
| F4 | 算法直接写 slot 而不经过 `gc_store_ref` | 跳过 write_barrier |
| F5 | `src/core/` 文件 include 算法私有头 | 方向错误：core 不依赖 algo |
| F6 | 在 algo 中重复实现 worklist/bitmap/card_table | 应复用 core |
| F7 | 在非 `GC_MULTITHREAD` 编译下使用 pthread | 条件编译未隔离 |
| F8 | 测试中使用 `printf` 作为验证手段（代替 `assert`） | 不可靠 |
| F9 | 改动 `include/xgc/*.h` 后不更新对应测试 | API 变化必须有测试覆盖 |
| F10 | 提交不通过 `-Werror` 的代码 | 零警告策略 |
