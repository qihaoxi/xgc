## Step A — 对象↔元数据映射机制

> **基础中的基础**：后续所有算法都靠它把 `gc_header*` 关联到算法私有元数据。先实现，否则 G/I/J 全部卡住。详见 [13](13-对象元数据映射实现.md)。

### A.1 选定并实现 inline-header 映射（Marksweep/RC 用）

- **文件**：`src/core/descriptor.c` 或算法私有文件（参考 13 §Scheme A）
- **实现点**：
  - `GcMsMeta` / `GcRcMeta` 结构置于 `gc_header` **之前**的内存布局
  - `meta_of(obj)` = `(GcXxMeta*)((char*)obj - sizeof(GcXxMeta))`，O(1) 反查
  - 分配时一次性申请 `sizeof(meta) + sizeof(header) + payload`，返回指向 header 的指针
- **注意**：
  - **释放时必须 `free(meta)` 而非 `free(obj)`**（13 §关键陷阱）——指针差了一个 meta 的偏移
  - meta 与 header 之间不能有编译器插入的 padding：用 `_Static_assert` 校验 `offsetof`
- **验收**：`meta_of(obj)` 往返一致；`test_meta_map_substrate` 中 inline 用例通过

### A.2 实现 side-table bitmap 映射（arena 型收集器用）

- **文件**：`src/core/bitmap.c`（已有）+ 映射封装
- **实现点**：
  - 对象地址 → bitmap 索引：`idx = (addr - arena_base) / min_obj_align`
  - 提供 `mark_index_of(obj)` / `obj_of_index(idx)`
- **注意**：要求对象在 arena 内按 `min_obj_align` 对齐，否则索引冲突
- **验收**：地址↔索引往返一致

### A.3 forwarding 映射（moving 算法用，gen-copy/compact/regional）

- **文件**：参考 13 §Scheme B
- **实现点**：
  - 复用 `desc` 字段最低位作 forwarding tag（对象已移动时存新地址）
  - `gc_forward_get(obj)` / `gc_forward_set(obj, new)`
- **注意**：tag 位会占用 desc 指针——desc 必须按 2 字节以上对齐（恒成立）；读 desc 处都要先清 tag
- **验收**：设置 forwarding 后 `gc_forward_get` 取回新地址，未设置时返回 NULL/自身

### A.4 元数据映射单元测试

- **文件**：`tests/test_meta_map_substrate.c` `(新建)`
- **实现点**：三种方案各一组往返用例 + 释放路径 ASan 干净
- **注意**：在 `cmake/tests.cmake` 用 `add_xgc_test` 注册
- **验收**：`ctest -R meta_map` 通过 + ASan 0 报错

## Step D — card_table 哈希优化

> 把 `gc_card_table_find_entry` 从 O(n) 升级为 O(1) 哈希，是分代写屏障性能的前提。

### D.1 开放寻址哈希表改造

- **文件**：`src/core/card_table.c`
- **实现点**：
  - `gc_card_table` 增 `size_t hash_mask`（capacity = 2^n，mask = capacity-1）
  - `register_owner`：`hash(owner_base)` → 线性探测找空槽插入
  - `find_entry`：`hash(owner_base)` → 线性探测查找，遇空槽停止
  - `unregister_owner`：写 tombstone（`owner_base = 1`），探测时跳过但不停止
  - 负载因子超阈值（如 0.75）时 rehash 扩容
  - hash 函数：
    ```c
    static size_t gc_card_table_hash(uintptr_t key, size_t mask) {
        key ^= key >> 16; key *= 0x45d9f3b; key ^= key >> 16;
        return (size_t)(key & mask);
    }
    ```
- **注意**：
  - tombstone 与空槽语义不同：查找遇 tombstone 要继续探测，遇真空槽才能断定不存在
  - rehash 时要重新插入所有非 tombstone 项，丢弃 tombstone
- **验收**：`ctest -R card_table` 通过

### D.2 同步 `gc_internal.h` 结构定义

- **文件**：`src/gc_internal.h`
- **实现点**：`gc_card_table` 增 `hash_mask` 字段
- **注意**：保持与 card_table.c 的字段顺序一致
- **验收**：构建通过

### D.3 更新 invariants

- **文件**：`src/core/invariants.c`
- **实现点**：`gc_card_table_check_invariants` 检查 `capacity` 是 2 的幂、`hash_mask == capacity-1`、非 tombstone 项数 ≤ capacity*负载上限
- **注意**：tombstone 不计入有效项，但占用槽位
- **验收**：`test_card_table_substrate` 通过 + ASan 干净

## Step F — 弱引用 + 终结器

> 详见 [08](08-弱引用与终结器.md)。前置 Step A、B。rc-cycle（G）依赖它。

### F.1 弱引用 slot 处理

- **文件**：`src/core/reclaim.c` 或算法 collect 路径、`include/xgc/gc_types.h`
- **实现点**：
  - descriptor 增 `gc_trace_weak_slots_fn` 回调 + `GC_DESC_FLAG_HAS_WEAK_SLOTS`
  - GC mark 完成后、sweep 前：遍历弱 slot，目标未标记则清 NULL
- **注意**：弱 slot **不参与可达性传播**（不能把目标加入 worklist）
- **验收**：仅弱可达对象被回收且 slot 被清 NULL

### F.2 引用强度层级（soft/phantom）

- **文件**：同上 + `src/core/reclaim.c`
- **实现点**：按 [08 §3.1](08-弱引用与终结器.md) 的顺序处理 soft→weak→finalizer→phantom
  - soft：按压力（12 §4）决定是否清；phantom：回收后入通知队列
- **注意**：**处理顺序不可乱**——soft 比 weak 强、phantom 最弱、finalizer 夹中间（有复活能力）
- **验收**：压力低时 soft 保留、压力高时 soft 清；phantom 的 get 永远 NULL

### F.3 两阶段终结模型

- **文件**：`src/core/reclaim.c`、finalizer 队列
- **实现点**：
  - mark 后识别"仅弱/软可达 + 带 finalizer"对象 → 入 finalize queue（**保持存活**，复活窗口）
  - rescan：从 finalize queue 出发重新标记（finalizer 可能复活引用）
  - drain queue：调用 finalizer；之后仍不可达才真正回收
- **注意**：
  - finalizer 只跑一次（标记 `finalized` 位防重入）
  - finalizer 内若复活对象，本轮不回收，下一轮按普通对象处理
- **验收**：无环对象 finalize 被调用一次；复活对象本轮存活

### F.4 弱引用 + 终结器测试

- **文件**：`tests/test_weak_ref_substrate.c`、`tests/test_finalize_substrate.c` `(新建)`
- **实现点**：覆盖 08 §4 交互矩阵的每一行
- **注意**：注册两个测试
- **验收**：`ctest -R 'weak_ref|finalize'` 通过 + ASan 干净

## Step G — rc-cycle 算法（Bacon-Rajan）

> 完整实现 RC + Trial-Deletion 环收集。详见 [05-D](05-算法实现详解.md)、[13](13-对象元数据映射实现.md)。前置 A、B、F。

### G.1 定义算法私有状态

- **文件**：`src/algo/bacon-rajan/gc_alloc.c`
- **实现点**：
  ```c
  typedef struct GcRcNode { gc_header* obj; uint32_t rc; uint32_t gc_ref;
      uint8_t color; uint8_t in_purple; struct GcRcNode* next; } GcRcNode;
  typedef struct { GcRcNode* objects; GcRcNode** purple_buffer;
      int purple_count, purple_capacity; } GcBaconRajanState;
  ```
  - 用 Step A.1 的 inline-header 把 `gc_header*` ↔ `GcRcNode` 关联
- **注意**：`rc` 只计**堆引用**，栈根不计数（栈靠 G.4 保护）
- **验收**：分配对象时 node 入全对象链表

### G.2 实现 write_barrier

- **文件**：`src/algo/bacon-rajan/gc_assign.c`
- **实现点**：
  - retain `new_value`：rc++
  - release `old_value`：rc--；==0 则 reclaim（递归 release 子节点）；>0 且未在紫缓冲则染紫入 buffer
- **注意**：
  - 必须先 retain 后 release（自赋值 `a=a` 时防止误回收）
  - 递归 release 用显式 worklist 防爆栈（13 §可编译模板）
- **验收**：引用增减后 rc 正确；rc 归零即时回收

### G.3 实现 collect_full（Trial Deletion 四阶段）

- **文件**：`src/algo/bacon-rajan/gc_collect.c`
- **实现点**：
  - Phase 1：紫缓冲对象 `gc_ref = rc`，染灰
  - Phase 2：DFS 子图，每条内部边令子 `gc_ref--`
  - Phase 3：`gc_ref>0`→存活(黑)，`==0`→垃圾(白)
  - Phase 4：回收白色；用 `desc->trace_slots` 遍历，用 `gc_worklist` 替代递归
- **注意**：颜色状态机不能错；Phase 2 不能漏边也不能重复减
- **验收**：自环、互环被回收

### G.4 栈根保护（Phase 2.5）

- **文件**：同 G.3
- **实现点**：Phase 2 后 Phase 3 前，扫描 roots：root 指向的 GRAY 对象递归回滚为 BLACK 且 `gc_ref++`
- **注意**：**漏掉此步会回收栈上正在用的环**（05-D §D.6）——这是最危险的 bug
- **验收**：根持有的环不被回收

### G.5 更新 vtable caps

- **文件**：`src/algo/bacon-rajan/` vtable 定义处
- **实现点**：`provides_deterministic_release=1`、`requires_write_barrier=1`，其余 0
- **注意**：caps 必须与实际函数指针一致，否则 `gc_runtime_validate_contracts` 启动即拒（见 [15](15-算法插件注册与切换.md)）
- **验收**：`gc_runtime_create` 不报契约错误

### G.6 smoke + 差分测试

- **文件**：`tests/test_bacon_rajan_smoke.c` `(新建)`
- **实现点**：5 场景——无环+finalize / 自环 / 双环 / 根持有 / handle 持有；并接入 [17](17-正确性验证与压力测试.md) 差分预言机
- **注意**：`cmake/tests.cmake` 用 `if(GC_ALGORITHM STREQUAL "bacon-rajan")` 条件注册
- **验收**：`-DGC_ALGORITHM=bacon-rajan` 下 smoke + 差分 + 压力全通过
